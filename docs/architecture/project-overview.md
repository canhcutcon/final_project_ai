## What This Project Is

This project is an **end-to-end anomaly-detection platform for tabular CSV data**, built around **Singapore real-estate transaction data** (property sales, rentals, commissions, and billing). A user uploads a CSV, the system profiles and validates it, runs machine-learning anomaly detection over every row, flags suspicious transactions, lets analysts triage each flag as an investigative *case*, and finally generates a natural-language audit report (Vietnamese/English) that can be exported to PDF.

It is organized as two cooperating repositories:

- **`csv_agent_services`** — the *product*: a FastAPI backend + Next.js frontend + Celery pipeline + MySQL/Redis/MinIO that an end user actually interacts with.
- **`csv_agent_platform`** — the *ML research/factory*: offline data-processing pipelines and model-training code that produce the detection model weights (V10/V11) and the report-generation LLM adapters (Qwen2 / Gemma) consumed by the product.

The intended users are **financial auditors, compliance analysts, and real-estate operations teams** who need to spot anomalous or fraudulent transactions (e.g. abnormal commission ratios, price outliers, duplicate invoices, suspiciously fast completions) without manually combing through spreadsheets. This is inferred from the domain rules in `{ai_services_detection}/configs/default.yaml` (commission-to-price ratios, agent velocity, billing mismatches), the audit-report prompts in `{ai_services_generation}/configs/generation_config.yaml`, and the CRM-style case-management UI in `{frontend}/components/anomaly/`.

## Core Capabilities

- **CSV upload & preview** — validates file type/size (≤100MB CSV), stores the raw file in MinIO, and returns a 10-row preview with column stats. `{backend}/app/api/endpoints/upload.py` + `{backend}/app/services/data_service.py`.
- **Schema mapping & rule-based validation (Upload Wizard)** — a 4-step wizard maps columns, applies rule sets, and surfaces hard-fails/soft-warnings before analysis. `{frontend}/components/upload/` + `{backend}/app/api/endpoints/validate.py`, `rules.py`, `templates.py`.
- **Asynchronous detection pipeline** — a 5-stage Celery chain (preprocess 20% → detect 60% → fix 75% → report 88% → export 100%) with live progress. `{backend}/app/tasks/pipeline_tasks.py`.
- **ML anomaly detection** — schema-agnostic V11 "universal" models (XGBoost + BiLSTM over a fixed 132-dim feature vector), V10 legacy fallback, IsolationForest last resort. `{backend}/app/services/ai_service.py` + `{backend}/app/ml/models/`.
- **Per-row explainability** — each anomaly carries top contributing fields (signed z-scores), expected-vs-actual ranges (numeric & categorical), and feature contributions (SHAP-style). `AIService.detect`, surfaced in `{frontend}/components/anomaly/`.
- **Case management (triage)** — analysts assign investigators, change case status, mark false positives, trigger ad-hoc rules per flagged row, and export evidence packets. `{backend}/app/api/endpoints/cases.py` + `{backend}/app/models/anomaly_case.py`.
- **AI-assisted data fixing** — Gemini suggests corrected values for flagged rows; high-confidence fixes auto-applied, low-confidence ones queued for human review. `{backend}/app/services/gemini_fix_service.py`, `{backend}/app/api/endpoints/agent.py`, `review.py`.
- **NLP report generation + PDF export** — turns detection results into a structured audit report via fine-tuned LLMs (template fallback) and exports to PDF. `{backend}/app/services/nlp_service.py`, `{backend}/app/ml/generation/`, `{ai_services_generation}/src/inference/`.
- **Dashboard & analytics** — summary metrics and weekly/monthly trend charts. `{backend}/app/api/endpoints/dashboard.py` + `{frontend}/app/(pages)/dashboard/`.
- **Offline ML data pipeline** — an 8-phase pipeline ingesting raw Prosage/SNRE files, cleaning, merging, feature-engineering, injecting synthetic anomalies, producing train/val/test datasets. `{ai_services_detection}/scripts/run_pipeline.py`.
- **Model training & promotion** — QLoRA fine-tuning of Qwen2-1.5B / Gemma-2-2B for report generation, plus detection model training/ablation notebooks. `{ai_services_generation}/src/training/`, `{ai_services_detection}/notebooks/`.

## System Components

- **`{frontend}` (Next.js 14 App Router, `csv_agent_services/fronted`)** — the browser UI. Owns the upload wizard, analyses list, anomaly drill-down + case triage, pipeline progress monitoring (WebSocket + polling), report viewing, templates management, and the dashboard. All backend access goes through a thin `fetch` wrapper in `{frontend}/lib/api.ts`.
- **`{backend}` (FastAPI, `csv_agent_services/backend`)** — the API tier. Owns HTTP/WebSocket endpoints, request validation, persistence (SQLAlchemy async + Alembic against MySQL), MinIO object storage access, launching the Celery pipeline, inference orchestration (`AIService`), and report/PDF generation (`NLPService`).
- **Celery worker (`{backend}/app/tasks/`)** — background processor running the 5-stage detection pipeline. Uses **synchronous** SQLAlchemy (pymysql) because workers are non-async; configured `solo` pool to keep native ML libs (XGBoost OpenMP / Torch) fork-safe (`{backend}/app/core/celery_app.py`).
- **`{ai_services_detection}` (`csv_agent_platform/detection`)** — offline detection ML. `scripts/run_pipeline.py` (8-phase data pipeline) produces processed datasets; `src/models/` defines model classes (XGBoost, BiLSTM, DAE, TranAD, AnoGAN, learned-hash); `notebooks/` trains versioned weights (v10, v11) and runs ablations/benchmarks. Trained weights are copied into `{backend}/app/ml/models/v10` & `v11` for serving.
- **`{ai_services_generation}` (`csv_agent_platform/generation`)** — offline report-generation ML. `src/aggregation/` + `src/enrichment/` shape detection output into a prompt; `src/inference/` routes to primary (Qwen2) / backup (Gemma) / template fallback; `src/training/` holds QLoRA fine-tuning scripts. LoRA adapters live in `{ai_services_generation}/models/`.
- **Infrastructure (docker-compose)** — MySQL 8 (datasets, analyses, pipelines, cases, reports), Redis (Celery broker + result backend), MinIO (raw CSVs, processed Parquet, PDFs).

## How It Fits Together

Primary end-to-end flow (upload → report):

```
                         ┌─────────────────────────────────────────────┐
                         │        Browser (Next.js {frontend})          │
                         │  upload wizard · analyses · case triage · UI │
                         └───────────────┬─────────────────────────────┘
                                         │ HTTP /api/v1/*  +  WS /pipeline/ws/{id}
                                         ▼
                         ┌─────────────────────────────────────────────┐
                         │           FastAPI {backend} (app.main)        │
                         │  endpoints → services → SQLAlchemy(async)     │
                         └───┬───────────────┬───────────────┬──────────┘
            upload raw CSV   │               │ enqueue chain │ read/write
                             ▼               ▼               ▼
                    ┌────────────┐   ┌──────────────┐   ┌─────────┐
                    │   MinIO    │   │ Redis (broker)│   │ MySQL   │
                    │ object store│  └──────┬───────┘   └─────────┘
                    └─────▲──────┘          │
                          │                 ▼
                          │      ┌────────────────────────────┐
                          │      │  Celery worker (5-task chain)│
                          └──────┤ preprocess→detect→fix→       │
                       Parquet/  │ report→export                │
                       PDF I/O   │  · AIService (V11 models)    │
                                 │  · NLPService (LLM report)   │
                                 └────────────────────────────┘

   Offline (separate repo, produces artifacts consumed above):
   {ai_services_detection} run_pipeline.py → datasets → train notebooks → v10/v11 weights
   {ai_services_generation} training → Qwen2/Gemma LoRA adapters
```

Integration points:

- **Frontend ↔ Backend** — HTTP JSON under `/api/v1` (base URL from `NEXT_PUBLIC_API_BASE_URL`) plus a WebSocket at `/api/v1/pipeline/ws/{id}` (`NEXT_PUBLIC_WS_URL`) for live pipeline updates.
- **Backend ↔ Worker** — Redis-backed Celery chain; the API fires `launch_pipeline(...)` fire-and-forget, the worker updates `PipelineRun.metrics.progress` + `current_step` in MySQL, which the WebSocket/polling endpoints relay back. If Celery is down, the API still creates records (pipeline stays `pending`).
- **Backend ↔ Storage** — MinIO holds the raw CSV (`storage_path`), the `_processed.parquet`, the `_fixed.parquet`, and `reports/report_{id}.pdf`.
- **Product ↔ ML factory** — *not* a live call: the platform repo produces model files offline that are checked into `{backend}/app/ml/models/v10` and `v11` and loaded by `AIService`'s `_ModelRegistry` singleton at first inference.

## How to Run

**Docker Compose (full stack), from `csv_agent_services/`:**

```bash
docker-compose up --build
docker-compose exec backend alembic upgrade head   # first-time DB setup
```

Ports: frontend `:3000`, API `:8000` (`/docs` for Swagger), MinIO console `:9001`, MySQL `:3307`, Redis `:6380`.

**Local development:**

```bash
# infra
cd csv_agent_services && docker-compose up db redis minio -d

# backend
cd csv_agent_services/backend
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
alembic upgrade head
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload

# celery worker (separate terminal)
cd csv_agent_services/backend && source venv/bin/activate
celery -A app.core.celery_app worker --loglevel=info --queues=main-queue --concurrency=2

# frontend
cd csv_agent_services/fronted
npm install && npm run dev
```

**Tests:**

- Backend: `cd csv_agent_services/backend && pytest` (config in `pytest.ini`).
- Frontend: `cd csv_agent_services/fronted && npx jest` (config in `jest.config.ts`).
- Generation/detection ML: `pytest` inside `csv_agent_platform/generation` / `csv_agent_platform/detection`.

**Offline ML pipeline:**

```bash
cd csv_agent_platform/detection
python scripts/run_pipeline.py --config configs/default.yaml --phase 0
```
