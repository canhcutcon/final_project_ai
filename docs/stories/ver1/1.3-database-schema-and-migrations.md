## Story

**As a** developer,  
**I want** the database schema created via Alembic migrations,  
**so that** schema changes are version-controlled and reproducible across environments.

## Acceptance Criteria

1: Thiết kế và tạo sẵn 4 bảng chính: `datasets`, `analysis_results`, `reports`, `pipeline_runs`.
2: Lệnh `alembic upgrade head` chạy thành công với MySQL dialect.
3: Các khóa ngoại (Foreign keys) và chỉ mục (Indexes) được thiết lập đúng cấu trúc thiết kế dữ liệu.

### Patterns & Conventions

- **Asynchronous Protocol**: Default to async SQLAlchemy (`ext.asyncio`) if suitable, otherwise blocking sync logic `create_engine()`. We expect FastAPI to operate Async reliably.
- **Relational Integrity**: Enforce constraints explicitly inside SQLAlchemy decorators.
- **Verification Rule**: AI developer agents must verify autogenerated `down_revision` outputs.

### Tech Stack

- **Python ORM**: SQLAlchemy 2.0+
- **Migrations**: Alembic Framework
- **Dialect Target**: MySQL (Driver likely `aiomysql` or `pymysql` depending on sync/async stance in codebase).

### Testing

- **Location**: `{backend}/tests/test_database.py`
- **Type**: Schema Integration verification. Tests should create a volatile in-memory SQLite schema equivalent OR provision a temporary MySQL harness bridging the Alembic context sequentially executing `head` and verifying creation logs.
