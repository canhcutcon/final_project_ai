# Story 3.5: Detection API & Model Registry

## Status

Draft

## Story

**As a** user,
**I want** an API endpoint to run the full 3-layer detection pipeline on my uploaded dataset,
**so that** I get detection results without manual configuration.

## Acceptance Criteria

1: `POST /api/v1/analysis/detect` body: `{"dataset_id": str, "config_override?": object}`
   - Pipeline: load data (Epic 2) → Layer 1 → Layer 2 → Layer 3 → Decision → save results
2: `GET /api/v1/analysis/{id}/results` returns per-row details:
   ```json
   [
     {
       "row_idx": 0,
       "decision": "flag",
       "anomaly_score": 0.87,
       "rule_score": 0.3,
       "rule_errors": [],
       "contributing_features": ["commission_ratio", "price_outlier"]
     }
   ]
   ```
3: Model Registry (`{ai_services_detection}/src/models/model_registry.py`):
   - Manage model versions, weights paths, metadata
   - `register_model(name, version, weights_path)`
   - `get_model(name, version?)` — auto load latest if version not specified
4: Results saved to `analysis_results` table: model_used, total_anomalies, total_rejected, total_flagged, anomaly_ratio, scores_json, metrics, duration_seconds
5: Metrics calculated: precision, recall, f1_score, auc_roc (if ground truth labels available)
6: Celery async task for pipeline execution (non-blocking API)
7: `GET /api/v1/analysis/{id}/status` returns pipeline progress:
   ```json
   {
     "status": "running",
     "current_step": "ml_detection",
     "steps": ["rule_validation", "rule_scoring", "ml_detection", "decision"],
     "progress_pct": 75
   }
   ```

### Patterns & Conventions

- **Backend layered architecture**: Controller (`api/endpoints/`) → Service (`services/`) → Model (`models/`)
- **Dependency injection**: FastAPI `Depends()` for DB sessions; module-level singletons for services
- **Error handling**: `HTTPException` with status codes 400/404/500, structured logging before raising
- **No standardized envelope**: Returns raw JSON (no `{ success: true, data: ... }` wrapper) — follow existing pattern
- **Celery tasks**: Defined in `core/celery_app.py`, Redis broker, `main-queue`
- **Pydantic schemas**: First DTOs in the project — establish the pattern in `app/schemas/`
- **API response format**: Match existing upload endpoint patterns (see `upload.py`)
- **Async**: FastAPI endpoints are async, DB operations via async SQLAlchemy session

### Tech Stack

- **FastAPI** >=0.110.0 — async API endpoints, `Depends()`, `BackgroundTasks`
- **Celery** — async pipeline execution via Redis broker
- **SQLAlchemy** >=2.0.29 — async ORM, `analysis_results` + `pipeline_runs` tables
- **Pydantic** (via pydantic-settings) — request/response schemas
- **Alembic** >=1.13.1 — DB migrations if schema changes
- **pytest** >=8.1.1 + pytest-mock — backend tests
- **httpx** >=0.27.0 — async HTTP testing
