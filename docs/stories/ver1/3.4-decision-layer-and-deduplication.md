# Story 3.4: Decision Layer & Deduplication

## Status

Draft

## Story

**As a** system administrator,
**I want** a unified decision layer that combines rule and ML results,
**so that** each row gets a single, consistent verdict (reject / flag / accept).

## Acceptance Criteria

1: `{ai_services_detection}/src/decision/decision_engine.py` implement `DecisionEngine` class
2: Decision logic (configurable thresholds):
   - `hard_fail` (from Layer 1) → **reject**
   - `rule_score >= 0.7 OR anomaly_score >= threshold` → **flag_for_review**
   - Else → **accept**
3: Deduplication: if rule AND ML both flag the same row, keep rule reason as primary, ML reason as supporting evidence
4: Output per row:
   ```json
   {
     "row_id": 1,
     "decision": "reject|flag|accept",
     "rule_errors": [{"field": "price", "error_type": "missing_value"}],
     "rule_score": 0.85,
     "anomaly_score": 0.92,
     "reasons": ["missing_price", "outlier_commission"],
     "needs_fix": true
   }
   ```
5: Decision thresholds configurable via config file (not hardcoded)
6: Feedback loop interface: `export_anomaly_patterns()` to suggest new rules from ML findings
7: Summary statistics: total_rejected, total_flagged, total_accepted, anomaly_ratio
8: `get_fixable_rows()` returns all rows needing fix (reject + flagged) with error context — this is input for Epic 7 Gemini Agent (Phase 2)

  - [ ] Create `{ai_services_detection}/src/decision/__init__.py`
  - [ ] Create `{ai_services_detection}/src/decision/decision_engine.py` with `DecisionEngine` class skeleton
  - [ ] Implement `__init__(self, config: dict)` loading decision thresholds from config: `rule_score_threshold` (default 0.7), `anomaly_score_threshold` (model-specific), `flag_score_threshold`

  - [ ] Define `RowDecision` dataclass: `row_id`, `decision`, `rule_errors`, `rule_score`, `anomaly_score`, `reasons: list[str]`, `needs_fix: bool`
  - [ ] Define `DecisionResult` dataclass: `rows: list[RowDecision]`, `summary: DecisionSummary`

- [ ] Task 2: Implement decision logic (AC: 2)
  - [ ] Implement `_decide_row(rule_result, score_result, anomaly_scores) -> RowDecision`
  - [ ] Priority: `has_hard_fail` → REJECT (highest priority, deterministic)
  - [ ] Then: `rule_score >= threshold OR anomaly_score >= threshold` → FLAG_FOR_REVIEW
  - [ ] Else: ACCEPT
  - [ ] Populate `needs_fix = True` for REJECT and FLAG_FOR_REVIEW rows
  - [ ] Collect all reasons from rule errors + triggered scoring rules + ML contributing features

- [ ] Task 3: Implement deduplication logic (AC: 3)
  - [ ] When both rule and ML flag the same row: rule reason = primary, ML reason = supporting evidence
  - [ ] Implement `_deduplicate_reasons(rule_reasons, ml_reasons) -> list[str]` — merge without double-counting
  - [ ] Tag each reason with source: `rule:missing_price`, `ml:outlier_commission`
  - [ ] If rule and ML detect the same underlying issue (e.g., both flag commission), consolidate into single reason with both sources noted

- [ ] Task 4: Implement main decide method (AC: 4, 7)
  - [ ] Implement `decide(validation_result, scoring_result, anomaly_scores) -> DecisionResult`
  - [ ] Accept inputs from Story 3.1 (`ValidationResult`), Story 3.2 (`ScoringResult`), Story 3.3 (`AnomalyScores`)
  - [ ] Iterate all rows, apply decision logic, collect `RowDecision` results
  - [ ] Compute summary statistics: total_rejected, total_flagged, total_accepted, anomaly_ratio
  - [ ] Add `to_dict()` / `to_json()` serialization for all result dataclasses

- [ ] Task 5: Implement get_fixable_rows for Epic 7 integration (AC: 8)
  - [ ] Implement `get_fixable_rows(decision_result) -> list[FixableRow]`
  - [ ] Define `FixableRow` dataclass: `row_id`, `decision`, `rule_errors` (full detail), `rule_score`, `anomaly_score`, `reasons`, `original_row_data: dict`
  - [ ] Filter: all rows with `needs_fix = True` (REJECT + FLAG_FOR_REVIEW)
  - [ ] Include full error context per row so Gemini Agent can understand and suggest fixes
  - [ ] Sort by severity: REJECT first, then FLAG_FOR_REVIEW sorted by combined score descending

- [ ] Task 6: Implement feedback loop interface (AC: 6)
  - [ ] Implement `export_anomaly_patterns(decision_result) -> list[SuggestedRule]`
  - [ ] Define `SuggestedRule` dataclass: `pattern_description`, `affected_rows_count`, `avg_anomaly_score`, `suggested_rule_type` (ERROR/WARNING), `confidence`
  - [ ] Analyze ML-only detections (flagged by ML but not by rules) → cluster by contributing features
  - [ ] Suggest new rules for recurring ML patterns (e.g., "15 rows flagged for high commission_ratio in district X — suggest AREA_SPECIFIC_COMMISSION rule")
  - [ ] Output as structured data for human review (not auto-applied)

- [ ] Task 7: Write tests (AC: 1-8)

  - [ ] Test deduplication: same row flagged by rule + ML → single merged entry
  - [ ] Test `get_fixable_rows()`: correct filtering, sorting, error context
  - [ ] Test `export_anomaly_patterns()`: ML-only detections produce suggestions
  - [ ] Test summary statistics: counts and ratios correct
  - [ ] Test threshold configurability: change thresholds via config, verify different decisions

### Patterns & Conventions

- **Class-based modules**: `DecisionEngine` receives `config: dict` in `__init__`
- **Config-driven thresholds**: All decision thresholds from `default.yaml` — add a `decision` section to config
- **Logging**: `get_logger(__name__)` with `%s` formatting
- **Type hints**: `X | Y` syntax, Google-style docstrings
- **No custom exception classes**: Use standard Python exceptions + structured result objects
- **Serialization**: All dataclasses should have `to_dict()` for JSON export (API consumption in Story 3.5)
