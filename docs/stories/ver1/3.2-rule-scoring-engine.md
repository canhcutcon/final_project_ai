# Story 3.2: Rule Scoring Engine (Layer 2 — Soft Rules)

## Status

Review

## Story

**As a** data analyst,
**I want** each row to receive a risk score based on soft rules,
**so that** suspicious but not invalid rows are flagged for further ML analysis.

## Acceptance Criteria

1: `{ai_services_detection}/src/rules/rule_scorer.py` implement `RuleScoringEngine` class
2: Scoring rules loaded from `{ai_services_detection}/configs/default.yaml` section `labels.domain_rules` — each rule has a calibrated `score` weight:
   - **HIGH_COMMISSION_RATIO** (score: 0.7): `gross_commission / transaction_price > 1.50` (150%) — catches data entry errors, not normal rental commissions
   - **FAST_COMPLETION** (score: 0.7): `completion_date - contract_date < 7 days` — suspicious speed
   - **PRICE_AREA_DEVIATION** (score: 0.5): price deviates > 300% from group median (grouped by `transaction_type`), min group size 30
   - **AGENT_VELOCITY** (score: 0.5): > 7 transactions/day/agent — SNRE has batch submissions
   - **BILLING_EXCEEDS_COMM** (score: 0.5): `billing_total / gross_commission > 1.15` (15% tolerance covers GST)
   - **NEGATIVE_VALUE** (score: 0.8): negative values in `transaction_price`, `gross_commission`, `billing_total`
   - **EXTREME_LEASE_DURATION** (score: 0.4): lease < 30 days or > 3650 days (10 years)
3: Additional scoring from `labels.anomaly_sources` section:
   - `HIGH_RISK` flag from `transaction-asian.xlsx` column
   - `PRICE_OUTLIER`: z-score > 5.0 on transaction_price
   - `SUSPICIOUS_DRAFT`: draft status + age > 730 days (2 years)
   - `BILLING_MISMATCH`: status = "Partially Invoiced"
   - `DUPLICATE_INVOICE`: matched from bills duplicate check report
4: Output per row: `{"row_id": int, "rule_score": 0.0-1.0, "triggered_rules": [{"rule": "HIGH_COMMISSION_RATIO", "score": 0.7, "detail": "ratio=2.3"}]}`
5: `rule_score` = weighted sum of triggered rule scores, normalized to [0, 1] — 0 = normal, 1 = very suspicious
6: Rule scores can be converted to features for ML Layer 3 (rule-to-feature bridge)
7: Scoring weights per rule type configurable in `default.yaml` (each rule has a `score` field)

### Completion Notes

**What was accomplished:**
- Created `{ai_services_detection}/src/rules/` Python module (AC 1)
- Implemented `RuleScoringEngine` in `{ai_services_detection}/src/rules/rule_scorer.py` loading weights from `configs/default.yaml` — zero hardcoded thresholds (AC 2, 7)
- All 7 domain rules wired to config: HIGH_COMMISSION_RATIO (0.7), FAST_COMPLETION (0.7), PRICE_AREA_DEVIATION (0.5), AGENT_VELOCITY (0.5), BILLING_EXCEEDS_COMM (0.5), NEGATIVE_VALUE (0.8), EXTREME_LEASE_DURATION (0.4)
- All 5 anomaly sources wired: HIGH_RISK (0.8), PRICE_OUTLIER (0.7), SUSPICIOUS_DRAFT (0.3), BILLING_MISMATCH (0.3), DUPLICATE_INVOICE (0.6) (AC 3)
- Per-row output matches AC 4 shape: `RowScoreResult(row_id, rule_score, [TriggeredRule(rule, score, detail)])`
- Capped-sum normalization `min(1.0, sum(scores))` — a single NEGATIVE_VALUE puts the row at 0.8 and a handful of concurrent rules saturate at 1.0 (AC 5)
- `to_features(df)` returns a DataFrame indexed like `df` with `rule_score`, `triggered_rule_count`, and stable `rule_<LABEL>` binary columns for each registered rule — the count is 2 + len(rule_registry), so downstream ML feature engineering has a fixed contract regardless of which rules fire on a given batch (AC 6)

**Design decisions:**
- Each `_check_*` method returns `(mask, details, label, score)` — a uniform contract that lets `score()` orchestrate row + dataset-level checks with one loop.
- Rule registry is built once at `__init__` from enabled config entries so `to_features` produces stable columns even when a rule never fires.
- Capped sum chosen over denominator-based normalization: ML features stay distributionally stable when rules are added/removed from config.
- `_calculate_row_score` kept as a static method so unit tests can exercise normalization in isolation without constructing an engine.
- `price_area_deviation` and `agent_velocity` operate on the full DataFrame in a single pass (dataset-level semantics) but emit per-row masks that merge into the same row buckets as row-level rules.

**Known limitations / follow-ups:**
- `suspicious_draft` uses `pd.Timestamp.now()` which makes the test output date-dependent — acceptable here because the cutoff is 730 days. If determinism is needed in CI, wire in a `clock` parameter.
- Story 3.1 (`rule_engine.py`) is not yet implemented — this story created `src/rules/__init__.py` minimally (exporting only the scorer). When Story 3.1 lands, its `RuleValidationEngine` can be added to `__init__.py` without breaking this module.
- Engine does not yet read `bills_duplicate_check_report_matches.csv` itself — caller must pass the DataFrame. Consistent with how `LabelEngineer._label_duplicate_invoice` handles it today.
