# Story 6.5: Pipeline Monitor with WebSocket

## Status

Draft

## Story

**As a** user,  
**I want** to see real-time pipeline progress with step-by-step updates,  
**so that** I can monitor and diagnose long-running backend analyses transparently.

## Acceptance Criteria

1: UI element `PipelineProgress`: step progress bar động ứng với 5 luồng worker của Celery.
2: Form options `PipelineConfig` cung cấp những rules trước khi chạy: auto_fix, language, report_style.
3: Cài đặt hooks `useWebSocket` để hứng chuỗi realtime status events từ FastAPI.
4: Render raw logs và các notifications / Error Messages chi tiết khi Celery worker bị drop/failed.

## Tasks / Subtasks

- [ ] Task 1: Pre-Execution Handlers (AC: 2)
  - [ ] Design the `PipelineConfig` overlay modal allowing the payload creation before initializing `run_full_pipeline`.
- [ ] Task 2: Dynamic WebSocket Hooks (AC: 3)
  - [ ] Build a robust Custom Hook `useWebSocket` in `{bafrontend}/src/hooks/useWebSocket.ts`. Support automatic reconnection behaviors on drops mapping native browsers WebSocket spec safely.
- [ ] Task 3: Stream Outputs & Trackers (AC: 1, 4)
  - [ ] Build the `PipelineProgress` linear stepper UI jumping across `Preprocess -> Detection -> Fixing -> Gen Report -> PDF Export` dynamically dependent on socket payload states.
  - [ ] Build `RawTerminal` console visualizer showing scrolling logging streams intercepting Celery exceptions and warnings directly. Highlight red aggressively upon Failures throwing errors.

### Patterns & Conventions
- `useEffect` cleanup handling is mandatory for WebSocket connections preventing infinite hanging socket listener ghost leaks on unmount.
- The UI styling must match the expected Cyberpunk minimal structure, simulating "hacker-like" system outputs efficiently for the terminal console logs.

### Tech Stack

- React Custom Hooks
