# Story 1.3: Layered mapping suggestion service

## Status

Draft

## Story

**As a** data operator,
**I want** the system to propose column mappings automatically,
**so that** I only correct exceptions instead of mapping everything by hand.

## Acceptance Criteria

1: `POST /api/v1/datasets/{id}/mapping/suggest` (body: `tdm_id`) returns per-source-column proposals: `{source_column, target_key | null, confidence, layer: exact|historical|llm|fuzzy}` implemented in a new `{backend}/app/services/mapping_service.py`
2: Layers execute in priority order — (1) exact/normalized name match (case, spacing, snake_case folding), (2) historical match from `mapping_history` by header signature and by individual header, (3) LLM semantic match, (4) fuzzy string match — first layer to produce a confident match wins
3: Matches below the configurable threshold (default 0.60, settable in app config) are returned with `target_key: null` (unmatched) for manual assignment
4: The LLM layer sends only column headers plus at most 5 sample values per column (NFR1) and is skipped entirely when the AI-disabled flag is set — the service degrades to fuzzy matching without error
5: Unit tests per layer with fixture files: exact-hit, historical-hit, semantic-hit (LLM mocked), fuzzy-hit, and no-hit below threshold

## Tasks / Subtasks

- [ ] Task 1 — App config additions (AC: 3, 4)
  - [ ] Subtask 1.1 Add `MAPPING_CONFIDENCE_THRESHOLD: float = 0.60` and `AI_MAPPING_ENABLED: bool = True` (the "AI-disabled flag") to `Settings` in `{backend}/app/core/config.py`, env-overridable like the existing `AUTO_FIX_CONFIDENCE_THRESHOLD` pattern
- [ ] Task 2 — `mapping_history` read/write helpers (AC: 2)
  - [ ] Subtask 2.1 Define the header-signature function (ordered list of normalized source headers, hashed per `tdm_id`) as a shared, reusable function — e.g. `{backend}/app/services/mapping_service.py::compute_header_signature(headers: list[str], tdm_id: int) -> str` — since Epic 1 Additional Notes require this to be shared with Story 1.4 and later Epic 5 pipeline execution; keep it import-safe (no circular deps) so other modules can reuse it
  - [ ] Subtask 2.2 Implement `lookup_historical_mapping(db, tdm_id, headers)`: full header-signature exact match first (confidence 1.0, per Story 1.4 AC4 "identical header signature auto-maps at confidence 1.0"); fall back to per-individual-header historical match from prior confirmed mappings for that `tdm_id`
- [ ] Task 3 — Exact/normalized match layer (AC: 2)
  - [ ] Subtask 3.1 Implement `_exact_match(source_headers, tdm_columns)`: normalize both sides (lowercase, strip, collapse whitespace/punctuation to `_`, snake_case fold) and match on exact normalized equality against each TDM column's `key` and `label`; confidence 1.0 on hit
- [ ] Task 4 — Historical match layer (AC: 2)
  - [ ] Subtask 4.1 Wire Task 2's `lookup_historical_mapping` into the layer chain; signature-level hits return confidence 1.0, individual-header hits return the confidence stored from the prior confirmation (or a fixed high confidence, e.g. 0.95, if mapping_history doesn't store a numeric score — decide and document this default in code)
- [ ] Task 5 — LLM semantic match layer (AC: 2, 4)
  - [ ] Subtask 5.1 Load the source file's sample values: `columns_info` on `Dataset` only stores `{column: dtype}` (see `{backend}/app/api/endpoints/upload.py`), not sample values — re-read the stored file via `minio_service.get_file_stream()` (`{backend}/app/services/storage.py`) and pull up to 5 sample values per column, per NFR1
  - [ ] Subtask 5.2 Build an LLM-backed matcher following the `GeminiFixService` pattern in `{backend}/app/services/gemini_fix_service.py`: batch call sending only `{source_column, sample_values[≤5]}` + the TDM's `{key, label, columnType, description}` list, expect strict JSON back (`{source_column, target_key|null, confidence}[]`), same retry/rate-limit handling (`MAX_RETRIES`, exponential backoff on 429), same Gemini→Ollama→manual-fallback degradation chain
  - [ ] Subtask 5.3 Skip this layer entirely (no error, just fall through to fuzzy) when AI is disabled — mirror the graceful-degradation pattern already used for missing Celery / missing model weights / missing WeasyPrint. **Resolve the effective flag via an explicit parameter, not a direct global read: `suggest_mapping(..., ai_enabled: bool | None = None)` uses `settings.AI_MAPPING_ENABLED` when `ai_enabled is None` and the passed value otherwise (see Subtask 7.1).** This keeps the global default for interactive callers while letting per-pipeline callers (Epic 5 Story 5.2's unattended execution) force AI off per-call — a hard requirement from 5.2, which reuses this exact function and cannot rely on a process-global flag.
- [ ] Task 6 — Fuzzy match layer (AC: 2, 3)
  - [ ] Subtask 6.1 No fuzzy-matching library exists in `{backend}/requirements.txt` today — add one (`rapidfuzz` is the common lightweight choice) or use stdlib `difflib.SequenceMatcher`/`get_close_matches` to avoid a new dependency; pick and document the choice, since both `backend` and `{ai_services_detection}` currently have zero fuzzy-matching deps
  - [ ] Subtask 6.2 Score each unmatched source column against every TDM column key/label; take the best score as the layer's confidence
- [ ] Task 7 — Orchestration + threshold gate (AC: 1, 2, 3)
  - [ ] Subtask 7.1 In `mapping_service.py`, implement `suggest_mapping(db, dataset_id, tdm_id, ai_enabled: bool | None = None) -> list[MappingProposal]`: for each source column, run layers 1→4 in order, stop at the first layer producing a match `>= settings.MAPPING_CONFIDENCE_THRESHOLD`, else fall through; if no layer clears the threshold, return `{source_column, target_key: None, confidence: <best score>, layer: <layer that produced it>}`. Compute the effective AI flag once at the top — `effective_ai = settings.AI_MAPPING_ENABLED if ai_enabled is None else ai_enabled` — and pass it into the LLM layer (Subtask 5.3). Interactive HTTP callers (Subtask 7.2) pass nothing (global default); Story 5.2 passes `ai_enabled=False` (or the pipeline's `enable_ai_for_unattended` config value).
  - [ ] Subtask 7.2 Add `POST /api/v1/datasets/{id}/mapping/suggest` to `{backend}/app/api/endpoints/datasets.py` (or a new `mapping.py` endpoint module mounted under the same `/datasets` prefix, consistent with `datasets.py`'s existing thin-router style): body `{tdm_id: int}`, 404 if dataset or TDM not found, calls `mapping_service.suggest_mapping` and returns the proposal list
- [ ] Task 8 — Tests (AC: 5)
  - [ ] Subtask 8.1 `{backend}/tests/test_mapping_service.py` with fixture CSV/header sets: exact-hit case (identical/near-identical headers), historical-hit case (pre-seeded `mapping_history` row), semantic-hit case (Gemini call mocked to return a JSON match), fuzzy-hit case (misspelled header, no history, AI disabled), and no-hit case (unrelated header, all layers below threshold → `target_key: null`)
  - [ ] Subtask 8.2 Test the `AI_MAPPING_ENABLED = False` path explicitly: assert the LLM layer is never invoked (mock asserts not called) and the result still degrades cleanly to the fuzzy layer

## Dev Notes

### Relevant Source Tree

- `{backend}/app/services/gemini_fix_service.py` — **the pattern to replicate** for the LLM layer: `GeminiFixService` class, `_init_model()` guarding on missing API key, `BATCH_SIZE`/`MAX_RETRIES`/`BASE_DELAY` class constants, `_call_gemini_batch` with 429/quota backoff, `_call_ollama_batch` local-model fallback via `urllib.request` to `OLLAMA_URL`/`OLLAMA_MODEL`, `_parse_response` defensive JSON parsing (strip code fences, clamp confidence to `[0,1]`, treat empty/no-op suggestions as zero-confidence), `_fallback_manual` when everything else fails. Reuse this exact structure for the new `MappingLLMMatcher` rather than inventing a new pattern.
- `{backend}/app/core/config.py` — `Settings(BaseSettings)`; existing precedent `AUTO_FIX_CONFIDENCE_THRESHOLD: float = 0.7` with an inline comment tying it to a spec section — add `MAPPING_CONFIDENCE_THRESHOLD` and `AI_MAPPING_ENABLED` the same way, env-overridable via `.env`.
- `{backend}/app/api/endpoints/datasets.py` — thin-router reference: `router = APIRouter()`, `Query(default=..., ge=..., le=...)` pagination style, `db.get(Dataset, id)` + `HTTPException(404, ...)` pattern. New mapping endpoint should match this style.
- `{backend}/app/api/endpoints/upload.py` — confirms `Dataset.columns_info` is only `{column_name: pandas_dtype_str}` — **no sample values are persisted**, so the LLM layer must re-fetch the file from storage rather than relying on `columns_info`.
- `{backend}/app/services/storage.py` — `MinioService` (`minio_service` singleton): `get_file_stream(object_name)` to re-read `dataset.storage_path` for sample-value extraction.
- `{backend}/requirements.txt` — no fuzzy-matching library present today; adding one is part of this story's scope (Task 6.1).
- Epic 1 file `final_project_ai/docs/prd/interactive-data-preprocessing/epic-1-target-data-models-and-column-mapping.md` — "Additional Notes": header-signature definition must be **shared code** between this story, Story 1.4, and Epic 5 pipeline execution — do not duplicate the normalization/hash logic per-caller.

### Patterns & Conventions

- **Architecture**: new business logic goes in a `services/` module (`mapping_service.py`), following the existing layered pattern — `api/endpoints` stays thin, `services` holds the layered-matching logic, `models`/`schemas` hold the DB and DTO shapes (`dataset_mappings`, `mapping_history` models land in Story 1.1's migration; this story is the first consumer).
- **Services are mostly stateless** with `@staticmethod`/module-level functions where possible, matching `AIService.detect` / `DataService.preprocess` style; if an LLM client needs lazy init/caching, follow the singleton-registry pattern already used for model weights (`AIService._ModelRegistry`).
- **DB access mode**: this is an HTTP-endpoint feature → **async** SQLAlchemy (`AsyncSession`, `Depends(get_db)`), not the sync Celery-task pattern.
- **Error handling**: `HTTPException(404, ...)` for missing dataset/TDM; unexpected errors logged via `logger.exception`/`logger.error` and re-raised as `HTTPException(500, detail=str(e))`. Graceful degradation is the dominant pattern in this codebase (missing Celery, missing model weights, missing WeasyPrint all degrade instead of erroring) — the missing-LLM / AI-disabled case in this story must follow the same convention: degrade to fuzzy, don't fail the request.
- **Logging**: `get_logger(__name__)` from `{backend}/app/core/logger.py`, `%`-style lazy formatting, never f-strings in `logger.*` calls.
- **JSON safety**: sanitize floats (`NaN`/`Inf` → `None`) before persisting confidence scores to JSON columns, per the `_sanitize_for_json`/`_clean` convention used elsewhere.
- **API response format**: no global envelope — return a flat JSON array of proposal objects, consistent with other list-shaped responses in this API.

### Tech Stack

- **Backend Framework**: FastAPI >=0.110.0, async endpoints via `Depends(get_db)`.
- **LLM — External API**: `google-generativeai` (`gemini-2.5-flash-lite`) for the semantic layer, with local Ollama (`qwen2.5:3b-instruct` via `OLLAMA_URL`/`OLLAMA_FIX_MODEL` env vars) as the same-prompt-contract fallback used by `gemini_fix_service.py` — reuse this exact dual-provider setup rather than calling Gemini only.
- **Object Storage**: MinIO (client >=7.2.5) via `minio_service` to re-read uploaded files for sample-value extraction.
- **Data Processing**: pandas for reading the file stream and pulling column sample values.
- **Fuzzy matching**: not currently a dependency — this story introduces one (recommend `rapidfuzz` for speed, or stdlib `difflib` to avoid adding a dependency; document whichever is chosen).
- **Testing**: pytest / pytest-mock >=8.1.1 for mocking the Gemini/Ollama calls in the semantic-hit and AI-disabled test cases.

### Notes from Previous Stories

- Story 1.1 creates the `target_data_models`, `dataset_mappings`, and `mapping_history` tables and adds `datasets.tdm_id` / `datasets.import_status` — this story is the first to read/write `mapping_history` and the first to query TDM column definitions (`key`, `label`, `columnType`, `description`) as the matching target set.
- Story 1.1's Alembic chain repair (missing `.py` migration sources) must land before this story's `mapping_history` reads/writes can be tested against a real schema.

### Testing

- Test file location: `{backend}/tests/test_mapping_service.py`, alongside the existing `tests/test_data_services.py`, `tests/test_router_accuracy.py`.
- Framework: pytest + pytest-mock, mocking the Gemini/Ollama HTTP calls (do not hit real external services in tests).
- Test types required: layer-by-layer unit tests (exact, historical, semantic-with-mocked-LLM, fuzzy, no-hit-below-threshold) plus an explicit test that the LLM layer is skipped and not invoked when `AI_MAPPING_ENABLED=False`.
- Use small in-memory/fixture header lists and a seeded `mapping_history` row rather than full CSV fixtures where possible, for speed; one fixture file is acceptable for the sample-value extraction path (Task 5.1).
