# Story 2.1: CSV Upload & Storage

## Status

Approved

## Story

**As a** user,  
**I want** to upload a CSV file through the API,  
**so that** my data is stored securely for analysis.

## Acceptance Criteria

1: Endpoint `POST /api/v1/upload` tiếp nhận file CSV multipart và lưu trực tiếp vào MinIO bucket.
2: Metadata thông tin cơ bản (filename, size, row_count, column_count, columns_info) được hệ thống ghi vào bảng `datasets` trong MySQL.
3: Cung cấp lại `dataset_id` trong phản hồi để sử dụng ở các bước tiếp theo.
4: Trả về lỗi `400 Bad Request` nếu file type không phải CSV hoặc dung lượng vượt quá giới hạn 100MB.

## Tasks / Subtasks

- [ ] Task 1: API Endpoint Setup (AC: 1, 4)
  - [ ] Implement `POST /api/v1/upload` in `{backend}/app/api/` using `UploadFile` (FastAPI).
  - [ ] Add content-type checks guaranteeing CSV constraints.
  - [ ] Add filesize validation halting at 100MB `HTTPException(400)`.
- [ ] Task 2: MinIO Storage Service (AC: 1)
  - [ ] Create `{backend}/app/services/storage.py` binding Python MinIO SDK.
  - [ ] Handle `put_object` logic returning the generated MinIO Object path (e.g. UUID filename).
- [ ] Task 3: Database Metadata (AC: 2, 3)
  - [ ] Using pandas initially on the uploaded stream to read `row_count` and `column_count`.
  - [ ] Insert `Dataset` record via SQLAlchemy asynchronous session containing size/path.
  - [ ] Return the generated `dataset_id` to the client.
