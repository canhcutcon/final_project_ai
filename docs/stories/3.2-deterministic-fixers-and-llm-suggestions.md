# Story 3.2: Deterministic fixers + LLM suggestions

## Status

Draft

## Story

**As a** data operator,
**I want** suggested fixes for detected issues,
**so that** cleaning is one click instead of manual editing.

## Acceptance Criteria

1: Rule-based fixers run first and are marked `source: rule`: date normalization to the TDM `outputFormat`, numeric coercion (strip currency symbols/thousand separators), whitespace/casing normalization, and category synonym mapping (incl. assignments remembered from Epic 1 confirm); each produces `{row, column_key, proposed_value, confidence}`
2: Issues left unresolved by rules are optionally sent to Gemini via the existing service wrapper — batched, error cells only with minimal row context (NFR1) — returning proposals marked `source: llm` with confidence; when the AI-disabled flag is set, this step is skipped silently
3: Suggestions can be applied one-by-one, all-per-column, or all-per-issue-type; every application writes a `transform_log` entry (original value, new value, actor, timestamp) and re-validates the affected cells
4: Numeric values flagged as outliers (`is_outlier_*`) are excluded from fix suggestions — they are flagged, never altered — with a test proving an extreme price is not "corrected"
5: The UI shows an explicit AI-processing notice the first time LLM suggestions are requested in a session (NFR1)

- [ ] Task 2 — Rule-based fixers (AC: 1)
  - [ ] Subtask 2.1 New module `{backend}/app/services/cleaning_service.py` (sibling to `validation_service.py`/`mapping_service.py`) implementing deterministic fixers, each returning `{row, column_key, proposed_value, confidence: 1.0, source: "rule"}`:
    - **Date normalization**: parse the raw value with `pd.to_datetime(..., errors="coerce")` and reformat to the TDM column's `outputFormat` (e.g. `strftime`) when parse succeeds
    - **Numeric coercion**: strip currency symbols (`$`, `€`, `£`, etc.), thousand separators (`,`), and whitespace, then attempt `float()`/`int()` per the column's `columnType`
    - **Whitespace/casing normalization**: `.strip()` + configurable case normalization (e.g. title-case for name-like `string` columns, upper-case for `category`/code-like columns) — scope this to obviously-safe cases (leading/trailing whitespace, internal double-spaces) rather than guessing intent for arbitrary text
    - **Category synonym mapping**: match the raw value against the TDM column's `dropdownOptions` using the `category_value_map` captured at Epic 1 Story 1.4's mapping confirm (source-value → target-option assignments) — this is the highest-confidence fixer since it replays a user-confirmed decision, not a guess
  - [ ] Subtask 2.2 Fixers only act on issues already recorded in `import_issues` (Story 3.1) — do not re-scan the whole dataset independently; take the issue list as input and return proposals only for issues each fixer can actually address
  - [ ] Subtask 2.3 Run fixers in a fixed, documented order (date → numeric → category-synonym → whitespace/casing, or whichever order minimizes double-fixing the same cell) and stop at the first fixer that produces a confident proposal for a given cell
- [ ] Task 3 — Outlier exclusion (AC: 4)
  - [ ] Subtask 3.1 **No `is_outlier_*` flag or reusable "compute outlier flags" utility currently exists anywhere in this codebase** (verified: no matches for `is_outlier` in `{backend}` or `{ai_services_detection}/src`). ### Patterns & Conventions

- **Backend architecture**: new `cleaning_service.py` module, layered the same way as `validation_service.py`/`mapping_service.py` — thin endpoints, logic in `services/`.
- **Graceful degradation**: AI-disabled → skip LLM step silently (no error), matching this codebase's dominant degradation pattern (missing Celery, missing model weights, missing WeasyPrint all degrade rather than fail).
- **Data minimization (NFR1)**: LLM batches must carry only the error cell + minimal row context, never the full row/dataset — follow `gemini_fix_service.py`'s existing `_build_prompt()` payload shape exactly.
- **Confidence semantics**: rule-based fixers are deterministic and should report `confidence: 1.0` (they either apply or they don't); LLM-sourced confidence follows the same `[0,1]` clamping and no-op/empty-value zeroing already implemented in `gemini_fix_service.py::_parse_response` — reuse that logic rather than reimplementing confidence sanitization.
- **Error handling**: `HTTPException(404, ...)` for missing dataset; `HTTPException(500, ...)` after `logger.exception(...)` for unexpected failures — consistent with the rest of the API.
- **Frontend state**: no global store; suggestions and the AI-notice-shown flag live in local component/page state, consistent with the rest of the upload wizard.
- **API response format**: no global envelope; flat JSON objects/arrays for suggestions and apply results, consistent with `report.py`'s `suggest-fix`/`apply-fix` response shapes.

### Tech Stack

- **LLM — External API**: `google-generativeai` (`gemini-2.5-flash-lite`) primary, local Ollama (`qwen2.5:3b-instruct`) fallback — same dual-provider stack as `gemini_fix_service.py` and Epic 1 Story 1.3's mapping LLM layer.
- **Data Processing**: pandas for all fixers (date parsing/formatting, numeric coercion, string normalization, duplicate/category checks).
- **Database**: MySQL via async SQLAlchemy for `transform_log` writes; bulk-insert for multi-cell applies.
- **Testing**: pytest/pytest-mock, mocking the Gemini/Ollama calls exactly as `gemini_fix_service.py`'s own usage would be tested (no real external calls).
