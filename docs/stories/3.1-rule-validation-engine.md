# Story 3.1: Rule Validation Engine (Layer 1 — Hard Rules)

## Status

Draft

## Story

**As a** data analyst,
**I want** the system to validate each CSV row against deterministic business rules,
**so that** obvious data errors are caught immediately before any ML processing.

## Acceptance Criteria

1: `{ai_services_detection}/src/rules/rule_engine.py` implement `RuleValidationEngine` class
2: Rules loaded from 2 config files in `{ai_services_detection}/configs/`: `business_rules.yaml` (13 rule sections — source of truth for hard validation) and `column_mapping.yaml` (canonical column names + variant mapping for schema standardization)
3: Hard fail checks (severity `ERROR`) based on `business_rules.yaml`:
   - **Field Type Enforcement** (Section 1): `force_string` fields (file_number, transaction_no, postal_code...) must not be parsed as numeric; `force_numeric` fields (transaction_price, gross_commission...) must strip currency patterns (`S$`, `,`) then convert; `date_columns` must be parseable datetime
   - **Required Fields by Transaction Type** (Section 2): `project_transaction` needs file_number, transaction_price, commission...; `normal_transaction` needs submission_date, property_type, address...; `prosage_non_project` needs representing, property_address
   - **Constraints** (Section 3): `file_number` must be not_null + unique
   - **Price/Status Rules** (Section 4): active transactions (status NOT Aborted/Draft) → `transaction_price`, `gross_commission`, `billing_total` must be > 0
   - **Commission Formula** (Section 5): `closing_agent + icb + ecb = gross_commission` (tolerance $1); commission/price ratio ≤ 10%
   - **Agent/Salesperson Validation** (Section 9): `reg_no` format `^R\d{4,6}[A-Z]$`; validate against SNRE Agent List; ECB/Referral must NOT be internal agent (leakage detection)
   - **Address Validation** (Section 10): postal code required (Singapore `\d{6}` pattern); column shift detection (address values in property_type column); valid property types enforcement
   - **Representing Values** (Section 13): must be one of `["Landlord", "Tenant", "Seller", "Buyer"]`
   - **Cross-field Relationships** (Section 13): billing_name required if billing_address exists; referral_commission required if referral_name exists; icb_commission required if icb_name exists
4: Warning-level checks (severity `WARNING`) based on `business_rules.yaml`:
   - **Entity Completeness** (Section 6): landlord/tenant name exists → at least 1 related field (NRIC, email, phone, UEN) must be filled
   - **Company Classification** (Section 7): name looks like company (PTE LTD suffix) but missing UEN → warning
   - **Company Dedup** (Section 8): normalized company names checked for duplicates across landlord/tenant/billing/ecb columns
   - **Entity Resolution** (Section 11): fuzzy name matching (threshold 0.85) across landlord/tenant identifiers; conflicting data → flag for human review
   - **JSON Array Validation** (Section 12): Prosage internal/external cobrokers JSON columns — key consistency across related columns
5: Column mapping uses `column_mapping.yaml` to normalize all column variants to canonical names before validation (e.g., `"Commssion+Tax"` typo → `commission_plus_tax`)
6: Output per row: `{"row_id": int, "errors": [{"field": "price", "error_type": "missing_value", "rule_section": "required_fields", "severity": "ERROR", "message": "..."}], "has_hard_fail": bool}`
7: `validate(dataframe) -> ValidationResult` processes entire dataset, returns list of row errors
8: Performance: validate 100K rows < 10 seconds
9: Config-driven: adding new rules only requires editing YAML sections, no code changes needed
10: Error output must be detailed enough (field, error_type, rule_section, severity) for Epic 7 Gemini Agent to understand context and suggest accurate fixes

### Patterns & Conventions

- **Class-based modules**: Each concern is a standalone class receiving `config: dict` in `__init__` — follow this pattern for `RuleValidationEngine`
- **Config loading**: Use `utils.helpers.load_config()` to load YAML files — never hardcode thresholds
- **Logging**: Use `get_logger(__name__)` with `%s` formatting (not f-strings)
- **Type hints**: `X | Y` union syntax (Python 3.10+), Google-style docstrings with `Args:` and `Returns:`
- **Naming**: `snake_case` for files/modules, `PascalCase` for classes
- **Error handling**: Graceful degradation — missing optional columns logged as `logger.warning()`, execution continues. `FileNotFoundError` for missing required inputs
- **No custom exception classes** — use standard Python exceptions + structured error dicts
- **Import order**: stdlib → third-party → local (`from src.`, `from utils.`)

### Tech Stack

- **Python** >=3.10 (union syntax `X | Y`)
- **pandas** >=2.0.0 — DataFrame operations, vectorized checks
- **PyYAML** >=6.0 — config loading via `load_config()`
- **rapidfuzz** (or similar) — fuzzy name matching for Section 11 entity resolution (threshold 0.85). Add to `requirements.txt` if not present
- **re** (stdlib) — regex for reg_no validation, postal code, currency stripping
- **pytest** >=7.4.0 — test framework with `conftest.py` shared fixtures

### Testing

- **Test location**: `{ai_services_detection}/tests/test_rule_engine.py`
- **Framework**: pytest >=7.4.0
- **Fixtures**: Extend `conftest.py` with rule-engine-specific fixtures (sample rows with various error types)
- **Test types**: Unit tests for each check method, integration test for full `validate()`, performance test for 100K rows
- **Pattern**: Each test function tests one check method with both valid and invalid inputs
