## Story

**As a** data analyst,
**I want** ML models to detect anomalies that deterministic rules cannot cover,
**so that** subtle and complex patterns (regional outliers, rare feature combinations) are caught.

## Acceptance Criteria

1: `csv_agent_platform/detection/notebooks/` implement 5 models in a single v10 notebook (continuing from v9):

- **XGBoost CLEAN** — primary supervised, V9 F1=0.88, 48 features without proxy
- **DAE + Mahalanobis** — unsupervised baseline, latent_dim=16
- **Attention-BiLSTM Autoencoder** — unsupervised, tabular feature sequence
- **BiLSTM Classifier** — semi-supervised, DAE latent + raw features
- **Ensemble stacking** — all models, auto-exclude harmful components
  > After results surpass targets → migrate to `csv_agent_services/src/models/` as separate class files inheriting `BaseAnomalyModel`
  > 2: **Attention-BiLSTM Autoencoder** (NEW — unsupervised):
- Input: tabular features as **feature sequence** `[batch, n_features, 1]` — each feature is 1 timestep, NOT time-series window aggregation (unlike V9 A5 which failed F1=0.498)
- Architecture: BiLSTM encoder (bidirectional, hidden=64, 2 layers) → Multi-head Self-Attention (4 heads) → LSTM decoder → reconstruct features
- Features sorted by semantic groups before feeding: Financial → Business Rule → Frequency → Temporal (meaningful feature ordering)
- Anomaly score = reconstruction error (MSE per row)
- Train on **normal-only data** (same as DAE training strategy)
- Attention weights exportable → contributing features (which features were hardest to reconstruct)
  3: **BiLSTM Classifier** (NEW — semi-supervised):
- Input: concatenate DAE latent representation (16-dim) + raw tabular features (48-dim) = 64-dim, reshape to sequence `[batch, 64, 1]`
- Architecture: BiLSTM encoder (bidirectional, hidden=64, 2 layers) → Attention pooling → FC layers `[128, 64, 1]` → sigmoid
- Train with labels from `is_anomaly` column + `biz_rule_violation_count` (semi-supervised: combine rule-based labels + model pseudo-labels)
- Class weighting: `W_ANOMALY=17.972`, `W_NORMAL=0.514` (from `default.yaml`)
- Output: anomaly probability [0, 1] per row
- Advantage over MLP (A8_SupervisedHead): BiLSTM captures sequential dependencies between latent features
  4: `load_model(weights_path)` loads pretrained weights from `.pt` files
  5: `predict(data: np.ndarray) -> AnomalyScores` returns anomaly scores per row
  6: XGBoost: feature importance per prediction (contributing_features)
  7: Attention-BiLSTM AE: attention weights per prediction (contributing_features from reconstruction difficulty)
  8: Ensemble: combine all model scores — auto-exclude models with negative weights (V9 strategy), nested val split for threshold tuning
  9: `BaseAnomalyModel` interface: `load_model()`, `predict()`, `get_threshold()`, `get_feature_importance()`
  10: Model inference on CPU (GPU optional), target < 30s for 100K rows
  11: Rule scores from Layer 2 can be added to feature set for ML models
  12: Fine-tuning support: `train(dataframe, labels?) -> ModelWeights` for all 4 models — allows retrain on new datasets

### Patterns & Conventions

- **Class-based modules**: Each model is a standalone class with `config: dict` in `__init__`
- **Config-driven**: All hyperparameters from `configs/default.yaml` — class_weights, latent_dim, hidden_dim, etc.
- **Device selection**: Use `utils.helpers.get_device()` → CUDA > MPS > CPU
- **Seed management**: Use `utils.helpers.set_seed()` for reproducibility
- **Data flow**: Input is `np.ndarray` (already scaled/selected), output is `AnomalyScores` dataclass
- **Model persistence**: PyTorch models saved as `.pt` via `torch.save()`, XGBoost as `.json`/`.pkl`, scalers as `.pkl` via `joblib`
- **Logging**: `get_logger(__name__)` with `%s` formatting
- **Type hints**: `X | Y` syntax, Google-style docstrings

### Tech Stack

- **PyTorch** >=2.0.0 — DAE, Attention-BiLSTM AE, BiLSTM Classifier architectures
- **XGBoost** — supervised detector (add to `requirements.txt` if not present)
