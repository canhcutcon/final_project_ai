# Story 1.5: Dynamic TDM suggestion

## Status

Draft

## Story

**As a** data operator onboarding a brand-new client format,
**I want** a draft TDM generated from my sample file,
**so that** I don't build the schema from scratch.

## Acceptance Criteria

1: "Suggest TDM from file" action on the TDM list page (and as a shortcut inside the wizard when no TDM fits) produces a draft definition — keys, labels, inferred columnTypes, and obvious validations (e.g. `required` for fully-populated columns, `regex` for email-shaped columns) — opened in the TDM editor; nothing is saved without explicit user confirmation
2: The LLM receives only headers plus a capped number of sample rows (≤ 20); the action is hidden when the AI-disabled flag is set
3: Draft quality benchmark: on the real-estate sample files used by the detection pipeline, ≥ 80% of columns receive a sensible `columnType` without manual correction (documented as a repeatable check, LLM output recorded in fixtures)

## Tasks / Subtasks

- [ ] Task 1 — Backend draft-generation endpoint (AC: 1, 2)
  - [ ] Subtask 1.1 Add `POST /api/v1/tdm/suggest` (body: `dataset_id`, or a direct file upload — decide based on whether the caller already has an uploaded `Dataset`; prefer `dataset_id` to reuse the existing upload flow and stay consistent with `mapping/suggest` in Story 1.3) to `{backend}/app/api/endpoints/tdm.py`
  - [ ] Subtask 1.2 Implement `suggest_tdm_draft(db, dataset_id)` in a new or shared service (co-locate with `mapping_service.py` from Story 1.3, e.g. `tdm_suggestion_service.py`, since both re-read the source file from MinIO): re-fetch the file via `minio_service.get_file_stream()`, cap sample rows sent to the LLM at ≤ 20 (AC2), and build a prompt requesting `{key, label, columnType, validations}` per header
  - [ ] Subtask 1.3 Reuse the `GeminiFixService`-style dual-provider pattern (Gemini primary, Ollama fallback) from `{backend}/app/services/gemini_fix_service.py` for the LLM call — same JSON-only response contract, same retry/backoff on 429, same defensive parsing
  - [ ] Subtask 1.4 Apply simple deterministic heuristics alongside the LLM output where the LLM is unavailable or low-confidence: `required` for columns with 0 nulls in the sample, `regex` (email pattern) for columns whose sample values all match an email shape — these act as a fallback/supplement, not a replacement, for the LLM's suggestions
  - [ ] Subtask 1.5 Return the draft as the same `TdmColumn[]` shape used by Story 1.1's schema (`key, label, columnType, description?, validations?`) — **do not persist anything**; this endpoint only returns a draft payload
  - [ ] Subtask 1.6 Skip the LLM call and return heuristics-only output (types inferred from pandas dtypes, no LLM-derived validations) when `settings.AI_MAPPING_ENABLED` (Story 1.3's AI-disabled flag) is `False` — reuse that same flag rather than introducing a second one, since Epic 1 treats "AI on/off" as a single app-config switch
- [ ] Task 2 — Frontend entry points (AC: 1, 2)
  - [ ] Subtask 2.1 Add a "Suggest TDM from file" action on the TDM list page (`{frontend}/app/(pages)/tdm/page.tsx`, from Story 1.2) that prompts for a dataset (reuse the existing upload flow / dataset picker) then calls the new `suggestTdmDraft(datasetId)` API function
  - [ ] Subtask 2.2 Add the same shortcut inside the upload wizard's Match Columns stage (`{frontend}/components/upload/SchemaMappingStep.tsx`, reworked in Story 1.4) for the case where no existing TDM fits — visible next to the TDM picker
  - [ ] Subtask 2.3 Hide both entry points when the AI-disabled flag is set — expose the flag's current value via a lightweight config/status read (e.g. an existing or new `GET /api/v1/config/flags`-style read, or piggyback on an existing settings-exposing endpoint if one exists) rather than hardcoding it client-side
  - [ ] Subtask 2.4 On response, open the draft directly in the TDM editor from Story 1.2 (table view pre-populated with the draft columns) — require an explicit "Save" action before anything is persisted (AC1 "nothing is saved without explicit user confirmation"); the editor's existing create/update flow already requires an explicit save, so no new persistence path is needed here
- [ ] Task 3 — API client function
  - [ ] Subtask 3.1 Add `suggestTdmDraft(datasetId)` to `{frontend}/lib/api.ts` using `apiFetch<T>`, returning `TdmColumn[]`

  - [ ] Subtask 4.2 Compute and print the percentage of columns whose suggested `columnType` matches the reference without manual correction; assert/report against the ≥ 80% target from AC3
  - [ ] Subtask 4.3 Save the LLM output + reference labels as fixture files under `{backend}/tests/fixtures/tdm_suggestion/` so the benchmark is reproducible and reviewable, not just a one-off manual run

  - [ ] Subtask 5.2 Frontend test for the "Suggest TDM from file" action being hidden when the AI-disabled flag is off, and for the draft correctly pre-populating the TDM editor state on success

## Dev Notes

### Relevant Source Tree

- `{backend}/app/services/gemini_fix_service.py` — dual-provider (Gemini → Ollama → fallback) pattern to reuse for the draft-generation LLM call, same as Story 1.3's semantic-match layer.
- `{backend}/app/services/mapping_service.py` (Story 1.3) — sibling service that already re-reads uploaded files from MinIO for LLM sampling; co-locate or share the "read file, take N sample rows" helper rather than writing a third copy of that logic (Story 1.3's LLM layer also needs this).
- `{backend}/app/services/storage.py` — `minio_service.get_file_stream()` for re-reading the source file by `dataset.storage_path`.
- `{backend}/app/core/config.py` — reuse `AI_MAPPING_ENABLED` (added in Story 1.3) as the single AI on/off flag for this story too, per Epic 1's Additional Notes ("Mapping confidence threshold, AI on/off flag live in app config").
- `{backend}/scripts/benchmark_latency.py` — existing benchmark-script convention (structure/CLI style) to mirror for the new `benchmark_tdm_suggestion.py`.
- `{ai_services_detection}/data/` — real-estate sample files already used by the detection pipeline; reuse these as the benchmark input rather than sourcing new fixtures, per AC3's explicit reference to them.
- `{frontend}/app/(pages)/tdm/page.tsx` and `{frontend}/components/upload/SchemaMappingStep.tsx` (from Stories 1.2/1.4) — the two entry points this story adds the "Suggest TDM from file" action to.
- `{backend}/app/schemas/tdm.py` (Story 1.1) — the `TdmColumn` schema the draft output must conform to.

### Patterns & Conventions

- **Architecture**: draft generation is a `services/` module following the same layered pattern as `mapping_service.py` — the endpoint (`tdm.py`) stays thin, calling into the service for the actual LLM/heuristic work.
- **Graceful degradation**: this is another instance of the codebase's recurring "AI unavailable → deterministic fallback, no error" pattern (missing Celery → pending; missing weights → IsolationForest; missing LLM here → dtype-based heuristics only). Follow it exactly — never fail the request because the LLM is unavailable.
- **No persistence in this endpoint**: unlike every other TDM/mapping endpoint in this epic, `/tdm/suggest` is read-only from the caller's perspective — it must not write to `target_data_models`. This is explicit in AC1 ("nothing is saved without explicit user confirmation") and is the main thing to verify in tests (Subtask 5.1).
- **Config flag reuse**: do not add a second "AI enabled" flag distinct from Story 1.3's `AI_MAPPING_ENABLED` — Epic 1 describes a single AI on/off switch shared across the mapping-suggestion and TDM-suggestion features.
- **Error handling**: `HTTPException(404, ...)` if `dataset_id` doesn't exist; unexpected errors logged via `logger.exception` and re-raised as `HTTPException(500, detail=str(e))`, consistent with the rest of the API.
- **API response format**: flat JSON array of `TdmColumn`-shaped objects, no envelope — consistent with `mapping/suggest`'s response shape from Story 1.3.

### Tech Stack

- Same LLM stack as Story 1.3: `google-generativeai` (`gemini-2.5-flash-lite`) primary, local Ollama (`qwen2.5:3b-instruct`) fallback.
- pandas for reading sample rows and computing dtype-based heuristics (null counts for `required`, regex matching for email-shaped columns).
- MinIO (`minio_service`) for re-reading the uploaded file.
- Testing: pytest/pytest-mock for mocked-LLM unit tests; the benchmark script is a standalone tool, not part of the pytest suite (mirrors `benchmark_latency.py`, which is also a script, not a test).

### Notes from Previous Stories

- Story 1.1 defines the `TdmColumn` schema (`key, label, columnType, validations, ...`) that this story's draft output must conform to exactly, since the draft is opened directly in Story 1.2's TDM editor.
- Story 1.2's TDM editor already has an explicit "Save"-gated create/update flow — this story does not need a new persistence mechanism, only a way to pre-populate that editor's in-memory `columns` state with the draft.
- Story 1.3 introduces `AI_MAPPING_ENABLED` and the MinIO-based sample-value re-fetch pattern; both are reused as-is here rather than duplicated.
- Story 1.4's Match Columns stage is where the second entry point ("no TDM fits") for this feature lives — implement this story's Task 2.2 against whatever that stage looks like after Story 1.4 lands.

### Testing

- Backend test file: `{backend}/tests/test_tdm_suggestion.py`, alongside `test_tdm.py` (Story 1.1) and `test_mapping_service.py` (Story 1.3).
- Framework: pytest + pytest-mock, mocking the LLM call (no real Gemini/Ollama calls in unit tests).
- Test types required: unit tests for draft shape correctness, no-persistence-as-a-side-effect, sample-row cap enforcement, and AI-disabled degradation; a separate, non-pytest benchmark script for the ≥ 80% quality target (AC3), with its output fixtures checked in for reviewability.
