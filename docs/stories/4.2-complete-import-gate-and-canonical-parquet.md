# Story 4.2: Complete-import gate & canonical Parquet

## Status

Draft

## Story

**As a** data operator,
**I want** "Complete import" to finalize the data and start the analysis,
**so that** only confirmed data enters the ML pipeline.

## Acceptance Criteria

1: "Complete import" is blocked while required-column errors remain, showing which columns/counts block it; a per-TDM setting switches the behavior to warn-and-proceed instead of block
2: On confirm: the canonical Parquet — human-readable values, TDM keys as column names, plus `is_outlier_*` flags where applicable — is written to MinIO as `*_canonical.parquet`; `datasets.import_status = confirmed` and `datasets.canonical_path` is set
3: The confirm action launches the existing Celery chain (`launch_pipeline` in `{backend}/app/tasks/pipeline_tasks.py`); the legacy auto-launch-on-upload flow remains available only behind a "quick mode" flag (NFR5)
4: Status/WebSocket endpoints report the pre-pipeline stages (`uploaded → structured → mapped → cleaning → reviewed → confirmed`) in addition to the Celery steps, so the frontend can render one continuous progress story
5: Confirming twice is idempotent (second confirm returns the existing pipeline run instead of double-launching)

## 🔌 Integration seams (this endpoint is a downstream integration point)

This story's `complete-import` endpoint is the success/finalization point that **two later stories hook into**. They were specified after this story and reference it by name, so build the seams now (Subtasks 4.5–4.6) rather than shipping 4.2 "done" and reopening it:
- **Story 5.2 (unattended execution)** resumes a paused `PipelineExecution` through this same endpoint (5.2 Subtask 3.4).
- **Story 5.3 (webhooks)** emits `import.completed` from this endpoint on success (5.3 Subtask 3.1).

Both seams are written to no-op cleanly when 5.2/5.3 aren't implemented yet, so this story remains independently shippable.

### Patterns & Conventions

- **Backend architecture**: new `import_completion_service.py`, layered like the rest of `services/`; the endpoint stays a thin orchestrator calling into it, mirroring how `start_analysis` itself is already fairly thin.
- **Idempotency via existing-record lookup before create**: this codebase already has this exact pattern in `analysis.py::start_pipeline` (look up an existing `PipelineRun` before deciding whether to create a new one or resume) — reuse it rather than inventing an idempotency key/mechanism.
- **Config-driven flags**: `Settings` fields for `QUICK_MODE_ENABLED`, following the established `AUTO_FIX_CONFIDENCE_THRESHOLD`/`AI_MAPPING_ENABLED`/`MAPPING_CONFIDENCE_THRESHOLD` precedent (inline comment tying it to its purpose/AC).
- **Graceful Celery-unavailable handling**: `start_analysis`'s existing `try/except` around `launch_pipeline` (log a warning, leave the run `pending` rather than failing the whole request) is the established convention — reuse it exactly.
- **Storage naming convention**: `_canonical.parquet` suffix, consistent with `_processed.parquet`/`_fixed.parquet`/`_agent_fixed.parquet` already in use.
- **Error handling**: `HTTPException(404, ...)` for missing dataset; a clearly-documented choice (409 vs. 200-with-blocked-flag — see Task 4.1) for the required-errors-block case, since no existing endpoint in this API has quite this shape; `HTTPException(500, ...)` after `logger.exception(...)` for unexpected failures.
- **API response format**: no global envelope; flat objects, consistent with `start_analysis`'s `{analysis_id, pipeline_id, message}` response shape.

### Tech Stack

- **Backend**: FastAPI >=0.110.0, async SQLAlchemy >=2.0.29, Celery[redis] >=5.3.0 (existing chain, unchanged entry point), Alembic >=1.13.1 for the `canonical_path`/TDM-setting migrations (blocked on Epic 1's chain repair).
- **Data Processing**: pandas + PyArrow for canonical Parquet read/write, consistent with existing Parquet usage throughout `pipeline_tasks.py`.
- **Object Storage**: MinIO via `minio_service`, unchanged interface.
- **Frontend**: Next.js/React/TypeScript, existing `useWebSocket` hook extended rather than replaced.
- **Testing**: pytest/pytest-mock/httpx, following `test_upload.py`'s established `AsyncClient` + `dependency_overrides` + `mocker.patch` conventions.
