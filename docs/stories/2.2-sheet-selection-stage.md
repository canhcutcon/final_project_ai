# Story 2.2: Sheet Selection stage

## Status

Draft

## Story

**As a** data operator,
**I want** to pick which worksheet to import,
**so that** multi-tab workbooks import the right data.

## Acceptance Criteria

1: For multi-sheet workbooks, the wizard presents a sheet picker listing each sheet with its row and column counts; the user's choice determines the grid used by all later stages
2: Single-sheet files (and all delimiter-based formats) skip this stage automatically — the progress bar shows it as completed, and the user can still navigate back to change it for workbooks
3: The selected sheet is recorded in the import lineage record (NFR4) and exposed by the dataset detail endpoint
4: Switching sheets after later stages have been touched resets downstream state (header selection, mapping) with an explicit confirmation dialog

## Dev Notes

### Relevant Source Tree

- `{backend}/app/api/endpoints/datasets.py` — thin-router reference (`list_datasets`, `get_dataset`) to extend with the new sheet endpoints; existing style: `Query(default=..., ge=..., le=...)`, `db.get(Dataset, id)` + `HTTPException(404, ...)`.
- `{backend}/app/models/dataset.py` — `Dataset` ORM to extend with `selected_sheet` (and related fields) via Alembic migration.
- `{backend}/app/services/storage.py` — `minio_service.get_file_stream()` to re-open the stored workbook for sheet enumeration.
- Story 2.1 (this epic) — establishes format detection (`file_format_service.py`) and the format-specific readers (`openpyxl` for XLSX/XLS, `odfpy` for ODS) this story reuses for sheet enumeration; Story 2.2 depends on Story 2.1 landing first since it needs to know which formats are workbook-shaped.
- `{frontend}/components/upload/WizardStepper.tsx` — **hardcoded 4-step stepper** (`Ingestion`, `Mapping`, `Validation`, `Inference`) that this story must extend with a new stage; this is the main frontend structural change.
- `{frontend}/app/(pages)/upload/page.tsx` — the wizard page holding all step state locally (no global store); this is where sheet-selection state, the touched-downstream-stages tracking (Task 6.1), and the confirmation-dialog trigger belong.
- `{frontend}/app/(pages)/templates/page.tsx` — reference for the native `confirm()` destructive-action-confirmation pattern to reuse for the sheet-switch warning (Task 6.2), rather than introducing a modal library.
- Epic 1 Story 1.1's Alembic migration chain — **currently broken** (no `.py` sources in `{backend}/alembic/versions/`, only stale bytecode); this story's new migration (Task 2.1) is blocked on that repair landing first.

### Patterns & Conventions

- **Backend architecture**: keep new sheet endpoints thin in `datasets.py`; if sheet-enumeration logic grows non-trivial (format-specific branching), extract it into `services/` (could live alongside Story 2.1's `file_format_service.py` as a natural sibling) rather than inlining it in the router.
- **DB access mode**: async SQLAlchemy (`AsyncSession`, `Depends(get_db)`) — this is an HTTP-endpoint feature, not a Celery task.
- **Error handling**: `HTTPException(404, ...)` for missing dataset/sheet; unexpected errors via `logger.exception` + `HTTPException(500, detail=str(e))`.
- **Frontend state management**: no global store — all wizard state (current step, per-step data, touched-stage tracking) lives in local component state in the page component, exactly as the current 4-step wizard already does.
- **Frontend confirmation pattern**: native browser `confirm()` for destructive/disruptive actions — this is the existing convention (`templates/page.tsx`'s delete flow), not a custom modal, for this class of interaction.
- **API response format**: no global envelope; sheet list is a flat JSON array (`[{name, row_count, column_count}]`); dataset detail stays a flat object with the new field added.
- **Naming/style**: Python 3.10+ type hints, `snake_case.py` backend filenames, `get_logger(__name__)` logging with `%`-style formatting; TypeScript 2-space indent, `"use client"` on interactive components, named exports for `lib/api.ts` functions.

### Tech Stack

- **Backend**: FastAPI >=0.110.0, async SQLAlchemy >=2.0.29, MySQL 8.0.35, Alembic >=1.13.1 (chain repair from Epic 1 Story 1.1 is a hard prerequisite for this story's migration).
- **File parsing**: `openpyxl` (already present) `read_only=True` mode for sheet enumeration on XLSX/XLS; `odfpy` (added in Story 2.1) for ODS sheet enumeration.
- **Object Storage**: MinIO via `minio_service`, unchanged.
- **Frontend**: Next.js 14.2.35 App Router, React 18, TypeScript ^5, Tailwind CSS — no new frontend dependencies needed; native `confirm()` for the reset-warning dialog.
- **Testing**: pytest/pytest-mock/httpx (backend, following `test_upload.py`'s `AsyncClient` + `dependency_overrides` + `mocker.patch` pattern); Jest + Testing Library (frontend).

### Notes from Previous Stories

- The full lineage record (NFR4) is an Epic 3 concern (Story 3.4); this story stores the sheet selection as a plain `Dataset` field/JSON blob as an interim measure, explicitly documented so Epic 3 can consume it later rather than re-deriving it — do not attempt to build the full lineage table in this story, that is out of scope.
