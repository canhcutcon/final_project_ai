# Story 2.2: Sheet Selection stage

## Status

Review

## Story

**As a** data operator,
**I want** to pick which worksheet to import,
**so that** multi-tab workbooks import the right data.

## Acceptance Criteria

1: For multi-sheet workbooks, the wizard presents a sheet picker listing each sheet with its row and column counts; the user's choice determines the grid used by all later stages
2: Single-sheet files (and all delimiter-based formats) skip this stage automatically — the progress bar shows it as completed, and the user can still navigate back to change it for workbooks
3: The selected sheet is recorded in the import lineage record (NFR4) and exposed by the dataset detail endpoint
4: Switching sheets after later stages have been touched resets downstream state (header selection, mapping) with an explicit confirmation dialog

### Patterns & Conventions

- **Backend architecture**: keep new sheet endpoints thin in `datasets.py`; if sheet-enumeration logic grows non-trivial (format-specific branching), extract it into `services/` (could live alongside Story 2.1's `file_format_service.py` as a natural sibling) rather than inlining it in the router.
- **DB access mode**: async SQLAlchemy (`AsyncSession`, `Depends(get_db)`) — this is an HTTP-endpoint feature, not a Celery task.
- **Error handling**: `HTTPException(404, ...)` for missing dataset/sheet; unexpected errors via `logger.exception` + `HTTPException(500, detail=str(e))`.
- **Frontend state management**: no global store — all wizard state (current step, per-step data, touched-stage tracking) lives in local component state in the page component, exactly as the current 4-step wizard already does.
- **Frontend confirmation pattern**: native browser `confirm()` for destructive/disruptive actions — this is the existing convention (`templates/page.tsx`'s delete flow), not a custom modal, for this class of interaction.
- **API response format**: no global envelope; sheet list is a flat JSON array (`[{name, row_count, column_count}]`); dataset detail stays a flat object with the new field added.
- **Naming/style**: Python 3.10+ type hints, `snake_case.py` backend filenames, `get_logger(__name__)` logging with `%`-style formatting; TypeScript 2-space indent, `"use client"` on interactive components, named exports for `lib/api.ts` functions.
