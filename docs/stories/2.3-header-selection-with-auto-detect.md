# Story 2.3: Header Selection with auto-detect

## Status

InProgress

## Story

**As a** data operator,
**I want** to confirm (or let the system detect) the header row,
**so that** columns are named correctly before mapping.

## Acceptance Criteria

1: Header Selection stage renders a raw grid preview with spreadsheet-style column letters (A, B, C…) and numbered rows; clicking a row selects it as the header, with rows above it excluded from data
2: Auto-detection proposes a header row with a confidence score (heuristics: type homogeneity below the candidate row, uniqueness and text-likeness of the candidate values); above the configurable threshold the stage is pre-completed but revisitable — Skip Header Step behavior
3: Advanced options: transpose rows/columns, and merge multiple consecutive header rows into one (values joined with a separator); both operations preview before applying
4: The confirmed header configuration (row index, transpose flag, merged rows) is recorded in lineage and contributes to the header signature used by mapping history (Epic 1); `import_status` advances to `structured`
5: The existing archetype detection (`tabular | timeseries | mixed` in `{backend}/app/services/data_service.py`) runs against the selected sheet + header configuration and its result is unchanged for current CSV fixtures (regression test)

## Dev Notes

### Relevant Source Tree

- `{backend}/app/services/data_service.py` — `DataService.detect_data_type()` (archetype detection: keyword/dtype/text-heuristics for `tabular`/`timeseries`/`mixed`) and `process_detected_type()` (background task, already modified in Story 2.1 Task 6 for format-agnostic reads) — this story changes *when* `detect_data_type` runs (post-header-confirm, not immediately post-upload) and must keep its output identical for existing CSV fixtures (AC5).
- `{backend}/app/core/config.py` — `Settings`; add `HEADER_DETECT_CONFIDENCE_THRESHOLD` next to the existing `AUTO_FIX_CONFIDENCE_THRESHOLD`/`MAPPING_CONFIDENCE_THRESHOLD` precedents.
- `{backend}/app/api/endpoints/datasets.py` — extend with raw-grid and confirm-header endpoints, following the existing thin-router style.
- `{backend}/app/api/endpoints/upload.py::preview_dataset` — existing 10-row **headered** preview pattern (`pd.read_csv(..., nrows=10)`, `_clean()` NaN/Inf scrubbing for JSON safety) to mirror for the new **un-headered** raw-grid endpoint, including the same float-sanitization step.
- Epic 1 Story 1.3's `{backend}/app/services/mapping_service.py::compute_header_signature()` — the shared function this story's output (final confirmed headers) feeds into; do not reimplement.
- Story 2.1 (this epic) — format-detection/readers this story reuses for the raw-grid read; Story 2.2 (this epic) — `selected_sheet` field and the interim structural-selection storage this story extends with header configuration, and the `WizardStepper.tsx`/wizard-page changes to coordinate with.
- `{frontend}/components/upload/WizardStepper.tsx` — hardcoded 4-step stepper needing a second extension (first extended in Story 2.2 for Sheet Selection, now again for Header Selection) — implement these together if both stories are in flight simultaneously to avoid rework.

### Patterns & Conventions

- **Backend architecture**: header-detection heuristics belong in a `services/` module, not inline in the endpoint — mirrors the layered pattern used throughout (`ai_service.py`, `data_service.py`, `mapping_service.py`).
- **Config-driven thresholds**: this codebase's established pattern (`AUTO_FIX_CONFIDENCE_THRESHOLD`, and Epic 1's `MAPPING_CONFIDENCE_THRESHOLD`) is a `Settings` field with an inline comment tying it to its spec/AC — follow exactly for `HEADER_DETECT_CONFIDENCE_THRESHOLD`, per Epic 2's explicit "Auto-detect thresholds are config values, not hardcoded" note.
- **JSON safety**: sanitize floats (`NaN`/`Inf` → `None`) in the raw-grid response exactly as `upload.py::preview_dataset`'s `_clean()` helper does, since raw un-headered reads are more likely to surface `NaN` cells (blank rows, ragged data).
- **Error handling**: `HTTPException(404, ...)` for missing dataset, `HTTPException(422, ...)` for invalid header/merge configuration, `HTTPException(500, ...)` after `logger.exception(...)` for unexpected failures.
- **Read-only previews before mutation**: transpose/merge (AC3) must be computable without persisting anything until the user explicitly confirms — consistent with this epic's general principle (also seen in Epic 1 Story 1.5's "nothing is saved without explicit user confirmation" for TDM drafts) that AI/heuristic proposals are always previewed before being written.
- **Frontend**: no global state — wizard-page-local `useState`; native Material Symbols icons and existing Tailwind semantic tokens (`bg-surface-container-lowest`, etc.) for the grid UI, matching `SchemaMappingStep.tsx`'s visual language.

### Tech Stack

- **Backend**: FastAPI >=0.110.0, pandas >=2.2.1 for un-headered reads (`header=None`) and transpose (`.T`), `openpyxl`/`odfpy` (from Story 2.1) for non-CSV raw-grid reads.
- **Config**: pydantic-settings >=2.2.1, env-overridable thresholds.
- **Testing**: pytest/pytest-mock/httpx, following the `AsyncClient` + `dependency_overrides` + `mocker.patch` pattern in `tests/test_upload.py`.
- **Frontend**: Next.js 14.2.35, React 18, TypeScript ^5, Tailwind CSS — no new dependencies expected; grid rendering can use plain HTML `<table>` (consistent with `SchemaMappingStep.tsx`'s existing table-based layout) rather than introducing a virtualization/grid library, since row counts previewed here are capped (Task 2.1) and small.

### Testing

- Framework: pytest + pytest-mock + httpx `AsyncClient`, same mocking conventions as the rest of the suite (`conftest.py` module stubs, no real DB/MinIO).
