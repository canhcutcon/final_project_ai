# Story 4.1: Aggregation Service

## Status

Draft

## Story

**As a** developer,
**I want** raw anomaly results grouped into semantic clusters with counts and summaries,
**so that** the LLM receives structured, pre-computed data instead of raw JSON.

## Acceptance Criteria

1: `{ai_services_generation}/src/aggregation/aggregation_service.py` implement `AggregationService` class
2: `AggregationService.aggregate(detection_result)` nhóm anomalies thành clusters theo `issue_type` (MISSING_TRANSACTION, HIGH_COMMISSION, DUPLICATE_ENTRY, ...)
3: Mỗi cluster chứa: `issue_type`, `count`, `samples[]` (top 3-5 mẫu đại diện), `affected_ids[]`
4: Context summary được tính toán sẵn: `total_records`, `expected`, `missing`, `anomaly_ratio`
5: Cross-analysis equations được sinh trước (VD: `-48 issued + 366 paid = 318 net difference`) — LLM chỉ cần rewrite, không tự tính
6: Output là structured JSON chuẩn, sẵn sàng cho Enrichment Layer
7: Unit tests tại `{ai_services_generation}/tests/test_aggregation.py`

## Tasks / Subtasks

- [ ] Task 1: Create generation service module structure (AC: 1)
  - [ ] Create `{ai_services_generation}/src/__init__.py`
  - [ ] Create `{ai_services_generation}/src/aggregation/__init__.py`
  - [ ] Create `{ai_services_generation}/src/aggregation/aggregation_service.py` with `AggregationService` class skeleton
  - [ ] Define typed dataclasses/models: `AnomalyCluster` (`issue_type: str`, `count: int`, `samples: list[dict]`, `affected_ids: list[str]`), `ContextSummary` (`total_records: int`, `expected: int`, `missing: int`, `anomaly_ratio: float`), `CrossAnalysisEquation` (`description: str`, `equation: str`, `result: float`), `AggregationResult` (`clusters: list[AnomalyCluster]`, `context: ContextSummary`, `cross_analysis: list[CrossAnalysisEquation]`)

- [ ] Task 2: Implement cluster grouping logic (AC: 2, 3)
  - [ ] Implement `_group_by_issue_type(detection_result) -> dict[str, list]` — group raw anomalies by `issue_type` field
  - [ ] Implement `_build_cluster(issue_type, anomalies) -> AnomalyCluster` — count anomalies, select top 3-5 representative samples (highest anomaly_score), collect all affected_ids
  - [ ] Handle edge cases: unknown issue_type → group under `OTHER`, empty anomalies → skip cluster

- [ ] Task 3: Implement context summary computation (AC: 4)
  - [ ] Implement `_compute_context(detection_result) -> ContextSummary` — extract total_records from dataset metadata, count expected vs missing, calculate anomaly_ratio as `anomaly_count / total_records`
  - [ ] Derive `expected` and `missing` from detection metadata fields (transaction counts, record completeness)

- [ ] Task 4: Implement cross-analysis equation generation (AC: 5)
  - [ ] Implement `_generate_cross_analysis(detection_result, clusters) -> list[CrossAnalysisEquation]` — compute arithmetic relationships between clusters
  - [ ] Generate equations like: issued vs paid differences, commission vs expected ratios, missing transaction counts
  - [ ] All numeric values pre-computed — output as human-readable equation strings for LLM rewrite

- [ ] Task 5: Implement main aggregate method (AC: 2, 6)
  - [ ] Implement `aggregate(detection_result: dict) -> AggregationResult` orchestrating: group → build clusters → compute context → generate cross-analysis
  - [ ] Validate input detection_result has required fields, raise `ValueError` with descriptive message if not
  - [ ] Output as structured dict via `.to_dict()` method on `AggregationResult` — JSON-serializable, ready for Enrichment Layer

- [ ] Task 6: Write unit tests (AC: 7)
  - [ ] Create `{ai_services_generation}/tests/__init__.py`
  - [ ] Create `{ai_services_generation}/tests/test_aggregation.py`
  - [ ] Test cluster grouping with mock detection results containing multiple issue_types
  - [ ] Test context summary computation with known values
  - [ ] Test cross-analysis equation correctness
  - [ ] Test edge cases: empty detection result, single anomaly, unknown issue_type
  - [ ] Test full `aggregate()` pipeline end-to-end with realistic sample data

### Patterns & Conventions

- **Python naming**: `snake_case` for files/modules, `PascalCase` for classes (e.g., `AggregationService`)
- **Type hints**: Use `X | Y` union syntax (Python 3.10+), type all public method signatures
- **Docstrings**: Google-style `"""triple-quote"""` with `Args:` and `Returns:` sections
- **Config-driven**: All thresholds (e.g., sample count 3-5) loaded from `configs/generation_config.yaml` via YAML, not hardcoded
- **Logging**: Use centralized `get_logger(name)` pattern, `%s` string formatting
- **No framework**: Pure Python with pandas/numpy — follows detection pipeline pattern
- **Error handling**: Graceful degradation — missing optional fields logged as warning, execution continues

### Tech Stack

- **Python** >=3.10 (union type syntax)
- **pandas** >=2.0.0 — DataFrame operations for grouping and aggregation
- **NumPy** >=1.24.0 — numerical computations for ratios and equations
- **PyYAML** >=6.0 — config loading
- **pytest** >=7.4.0 — unit testing

### Testing

- **Framework**: pytest >=7.4.0
- **Fixtures**: Create `conftest.py` with shared fixtures (sample detection results, expected outputs)
- **Test types**: Unit tests for each method, integration test for full `aggregate()` pipeline
- **Pattern**: Follow detection test structure — `conftest.py` for shared fixtures, descriptive test names
