# Story 2.1: Multi-format upload

## Status

Review

## Story

**As a** data operator,
**I want** to upload XLSX/XLS/TSV/PSV/ODS in addition to CSV,
**so that** I don't have to convert files manually.

## Acceptance Criteria

1: `POST /api/v1/upload` in `{backend}/app/api/endpoints/upload.py` accepts `.csv`, `.xlsx`, `.xls`, `.tsv`, `.psv`, `.ods` with the existing 100 MB limit; the parser is selected by sniffing content (magic bytes / delimiter detection), not by extension alone
2: Corrupt, empty, or password-protected files are rejected with actionable error messages (e.g. "File appears to be password-protected — remove the password and re-upload"), never a bare 500
3: XLSX reads are memory-safe for large files (streamed/chunked via openpyxl read-only mode where possible) per NFR7
4: The existing CSV upload path is unchanged in behavior — covered by a regression test — and the response contract (dataset id, row/column counts, preview availability) is preserved for all formats
5: Uploaded raw file is stored in MinIO as today; `datasets.import_status` is set to `uploaded`

### Patterns & Conventions

- **Backend architecture**: keep the endpoint thin — move format-sniffing and per-format parsing logic into a `services/` module (`file_format_service.py`) rather than growing `upload.py`'s route function further, consistent with the layered `api/endpoints` → `services` separation used elsewhere (e.g. `ai_service.py`, `data_service.py`).
- **Error handling**: raise `fastapi.HTTPException(status_code=400, detail="<actionable message>")` for all known bad-input cases (corrupt/empty/password-protected) — this codebase's established convention reserves `500` for genuinely unexpected errors only, caught via a final `except Exception` + `logger.exception(...)`. AC2's "never a bare 500" requirement means these specific failure modes must be positively caught before the generic handler, not just documented.
- **Graceful degradation** is the dominant pattern elsewhere in this codebase (missing Celery, missing model weights, missing WeasyPrint all degrade instead of failing) — for corrupt/unreadable files there's no graceful degradation possible, so the correct move here is a clear 400, not degradation.
- **Logging**: `get_logger(__name__)` from `{backend}/app/core/logger.py`, `%`-style lazy formatting (`logger.warning("Invalid file type: %s", ...)`), never f-strings inside `logger.*` calls — match the existing style already in `upload.py`.
- **Import ordering / lazy imports**: heavy/optional imports (e.g. `openpyxl.load_workbook` for the read-only large-file path) should be imported lazily inside the function that needs them, per this codebase's convention of keeping startup fast and missing deps non-fatal elsewhere.
- **API response format**: no global envelope; keep the exact existing success shape `{"dataset_id": int, "message": str}` and FastAPI's default `{"detail": "<message>"}` error shape.

### Completion Notes
