# Story 2.1: Multi-format upload

## Status

Approved

## Story

**As a** data operator,
**I want** to upload XLSX/XLS/TSV/PSV/ODS in addition to CSV,
**so that** I don't have to convert files manually.

## Acceptance Criteria

1: `POST /api/v1/upload` in `{backend}/app/api/endpoints/upload.py` accepts `.csv`, `.xlsx`, `.xls`, `.tsv`, `.psv`, `.ods` with the existing 100 MB limit; the parser is selected by sniffing content (magic bytes / delimiter detection), not by extension alone
2: Corrupt, empty, or password-protected files are rejected with actionable error messages (e.g. "File appears to be password-protected — remove the password and re-upload"), never a bare 500
3: XLSX reads are memory-safe for large files (streamed/chunked via openpyxl read-only mode where possible) per NFR7
4: The existing CSV upload path is unchanged in behavior — covered by a regression test — and the response contract (dataset id, row/column counts, preview availability) is preserved for all formats
5: Uploaded raw file is stored in MinIO as today; `datasets.import_status` is set to `uploaded`

## Tasks / Subtasks

- [ ] Task 1 — Add ODS support dependency (per Epic 2 Dependencies)
  - [ ] Subtask 1.1 Add an ODS-reading library to `{backend}/requirements.txt` (`odfpy` is pandas' documented ODS engine — `pd.read_excel(..., engine="odf")`); `openpyxl` (XLSX/XLS-adjacent) is already a platform dependency and needs no addition
- [ ] Task 2 — Content-sniffing format detector (AC: 1)
  - [ ] Subtask 2.1 Implement a `detect_file_format(file_bytes: bytes, filename: str) -> str` helper (new module, e.g. `{backend}/app/services/file_format_service.py`) that sniffs magic bytes first — ZIP signature `PK\x03\x04` for `.xlsx`/`.ods` (both are zip containers; disambiguate by inspecting the zip's `mimetype`/`[Content_Types].xml` entry), OLE2 signature `\xD0\xCF\x11\xE0` for legacy `.xls` — and falls back to delimiter sniffing (`csv.Sniffer` or a simple comma/tab/pipe frequency count on the first lines) for text-based `.csv`/`.tsv`/`.psv` when magic bytes don't match a binary container
  - [ ] Subtask 2.2 Use the detected format to choose the read path — do **not** trust `file.filename`'s extension or `file.content_type` alone (AC1 explicitly requires content sniffing, not extension-only dispatch as today's `upload_csv` does with its `.endswith(".csv")` check)
- [ ] Task 3 — Format-specific readers (AC: 1, 3)
  - [ ] Subtask 3.1 CSV/TSV/PSV: `pd.read_csv(file.file, sep=detected_delimiter)` — delimiter (`,`, `\t`, `|`) comes from Task 2's sniffing
  - [ ] Subtask 3.2 XLSX: `pd.read_excel(file.file, engine="openpyxl")`; for the memory-safety requirement (AC3, NFR7) use `openpyxl.load_workbook(..., read_only=True)` directly for the row/column-count inspection pass on large files rather than materializing the full frame twice, matching the "streamed/chunked where possible" wording in AC3 — document the chosen approach's actual memory ceiling in code comments since full `pd.read_excel` still loads the sheet into memory once
  - [ ] Subtask 3.3 XLS (legacy): `pd.read_excel(file.file, engine="xlrd")` — note `xlrd` is not currently in `requirements.txt`; verify whether pandas' installed version still supports legacy `.xls` via `xlrd>=2.0` (xlrd 2.x dropped xlsx support but still reads `.xls`) and add it explicitly if missing
  - [ ] Subtask 3.4 ODS: `pd.read_excel(file.file, engine="odf")` using the new `odfpy` dependency
  - [ ] Subtask 3.5 Refactor `upload_csv` (rename to a format-agnostic handler internally, keep the route path `POST /api/v1/upload` unchanged) to dispatch to the correct reader based on Task 2's detection result, producing the same `row_count`/`column_count`/`columns_info` triple regardless of format (AC4)
- [ ] Task 4 — Actionable error handling (AC: 2)
  - [ ] Subtask 4.1 Catch `zipfile.BadZipFile` / `openpyxl`'s encrypted-workbook exception (`openpyxl.utils.exceptions.InvalidFileException`, or detect an OLE2-encrypted container signature before attempting to parse) and raise `HTTPException(400, detail="File appears to be password-protected — remove the password and re-upload.")`
  - [ ] Subtask 4.2 Catch `pd.errors.EmptyDataError` (existing) plus empty-sheet equivalents for Excel/ODS (0 rows after header) and return the existing-style "The provided CSV/file is empty." message, generalized to name the actual format
  - [ ] Subtask 4.3 Catch generic corrupt-file parse failures (`pd.errors.ParserError`, `zipfile.BadZipFile`, `openpyxl` load errors) and map them to a `400` with a specific actionable message rather than letting them fall through to the existing bare `except Exception` → `HTTPException(500, detail=str(e))` path — AC2 explicitly requires "never a bare 500" for these cases
  - [ ] Subtask 4.4 Add a clear "unsupported file format" `400` for content that doesn't sniff as any of the 6 supported formats — this replaces today's extension/content-type-based `"Only CSV files are allowed."` rejection in `upload.py:24-26`; update the existing `test_upload_invalid_type` test in `{backend}/tests/test_upload.py` (currently asserts `"Only CSV files"` in the response for a `.txt` upload) to assert the new message text instead, since AC1 changes the rejection to be content-sniffing-based rather than extension-based
- [ ] Task 5 — Preserve response contract + `import_status` (AC: 4, 5)
  - [ ] Subtask 5.1 Keep the response shape `{"dataset_id": ..., "message": "File uploaded successfully"}` identical across all formats
  - [ ] Subtask 5.2 Set `dataset_record.import_status = "uploaded"` on the new `Dataset.import_status` column (added in Epic 1 Story 1.1's migration) at creation time — today's code doesn't set this field at all since it predates Epic 1; this story is the first writer of `import_status`
  - [ ] Subtask 5.3 Storage: keep using `minio_service.upload_file()` unchanged — store the raw uploaded bytes regardless of format, exactly as CSV is stored today
- [ ] Task 6 — Downstream background task compatibility (AC: 4)
  - [ ] Subtask 6.1 `{backend}/app/services/data_service.py::process_detected_type` currently hardcodes `pd.read_csv(io.BytesIO(content))` when it re-reads the file from MinIO after upload — this will break (or silently misparse) for any non-CSV upload; update it to reuse Task 2's `detect_file_format` + Task 3's format-specific reader dispatch so archetype detection and preprocessing still run correctly for XLSX/XLS/TSV/PSV/ODS uploads. This is not explicitly in the epic's ACs but is required for AC4 ("existing CSV path unchanged... preserved for all formats") to hold end-to-end rather than just at the upload response
- [ ] Task 7 — Tests (AC: 2, 4)
  - [ ] Subtask 7.1 Add fixture files under `{backend}/tests/fixtures/upload_formats/` for each of `.csv`, `.xlsx`, `.xls`, `.tsv`, `.psv`, `.ods`, plus a corrupt file, an empty file, and a password-protected `.xlsx`
  - [ ] Subtask 7.2 Regression test: existing CSV upload behavior (response shape, row/column counts, preview availability via `GET /{dataset_id}/preview`) is byte-for-byte unchanged — add this as an explicit test named to make its regression purpose clear (e.g. `test_upload_csv_regression`)
  - [ ] Subtask 7.3 Per-format happy-path test asserting `dataset_id`, correct `row_count`/`column_count`, and `import_status == "uploaded"`

## Dev Notes

### Relevant Source Tree

- `{backend}/app/api/endpoints/upload.py` — **the file this story rewrites**. Today: `upload_csv()` checks only `file.filename.endswith(".csv")` or `content_type in ["text/csv", "application/vnd.ms-excel"]` (note: `application/vnd.ms-excel` is already accepted by content-type today but the body still force-parses with `pd.read_csv`, so legacy `.xls`-labeled uploads currently silently mis-parse or fail — this story fixes that properly), enforces the 100MB cap via `file.file.seek(0,2)`/`tell()`, reads with `pd.read_csv(file.file)` unconditionally, computes `columns_info = {col: str(dtype)}`, stores via `minio_service.upload_file()`, creates a `Dataset` row with `data_type="detecting"`, and enqueues `DataService.process_detected_type` as a background task. `preview_dataset()` in the same file also hardcodes `pd.read_csv` when re-reading from MinIO for the 10-row preview — out of this story's explicit AC scope but worth flagging as a related follow-up if preview breaks for non-CSV formats (not required by the ACs above, so only fix if time allows; do not silently skip it without a task note if left undone).
- `{backend}/app/services/data_service.py` — `process_detected_type()` background task also hardcodes `pd.read_csv(io.BytesIO(content))`; must be updated per Task 6 for archetype detection to keep working on non-CSV uploads.
- `{backend}/app/services/storage.py` — `minio_service.upload_file()` / `get_file_stream()`, unchanged by this story; format-agnostic already (stores raw bytes).
- `{backend}/app/models/dataset.py` — `Dataset` ORM; `import_status` column exists from Epic 1 Story 1.1 but nothing writes to it yet — this story is the first writer.
- `{backend}/requirements.txt` — `pandas>=2.2.1` present; `openpyxl` already listed as a platform dependency (per tech-stack.md, used for "Read Prosage XLSX" elsewhere); `odfpy` (ODS) and possibly `xlrd` (legacy XLS) are **not currently listed** and must be added.
- `{frontend}/components/upload/` `DropZone` (inline in the `(pages)/upload/page.tsx` file) — the file `<input>` currently has `accept=".csv"`, restricting the OS file picker to CSV only; this must be widened to include the new formats so users can actually select them (`accept=".csv,.xlsx,.xls,.tsv,.psv,.ods"`). This is a small but necessary frontend touch even though the epic's ACs are backend-focused.
- `{frontend}/lib/api.ts` — `uploadCSV(file)` sends `FormData` to `/upload` with no client-side extension check; no change needed to this function itself beyond the DropZone's `accept` attribute update.

### Patterns & Conventions

- **Backend architecture**: keep the endpoint thin — move format-sniffing and per-format parsing logic into a `services/` module (`file_format_service.py`) rather than growing `upload.py`'s route function further, consistent with the layered `api/endpoints` → `services` separation used elsewhere (e.g. `ai_service.py`, `data_service.py`).
- **Error handling**: raise `fastapi.HTTPException(status_code=400, detail="<actionable message>")` for all known bad-input cases (corrupt/empty/password-protected) — this codebase's established convention reserves `500` for genuinely unexpected errors only, caught via a final `except Exception` + `logger.exception(...)`. AC2's "never a bare 500" requirement means these specific failure modes must be positively caught before the generic handler, not just documented.
- **Graceful degradation** is the dominant pattern elsewhere in this codebase (missing Celery, missing model weights, missing WeasyPrint all degrade instead of failing) — for corrupt/unreadable files there's no graceful degradation possible, so the correct move here is a clear 400, not degradation.
- **Logging**: `get_logger(__name__)` from `{backend}/app/core/logger.py`, `%`-style lazy formatting (`logger.warning("Invalid file type: %s", ...)`), never f-strings inside `logger.*` calls — match the existing style already in `upload.py`.
- **Import ordering / lazy imports**: heavy/optional imports (e.g. `openpyxl.load_workbook` for the read-only large-file path) should be imported lazily inside the function that needs them, per this codebase's convention of keeping startup fast and missing deps non-fatal elsewhere.
- **API response format**: no global envelope; keep the exact existing success shape `{"dataset_id": int, "message": str}` and FastAPI's default `{"detail": "<message>"}` error shape.

### Tech Stack

- **Backend Framework**: FastAPI >=0.110.0, `UploadFile`/`File(...)` for multipart uploads (`python-multipart` >=0.0.9 already a dependency).
- **Data Processing**: pandas >=2.2.1 for all format reads; `openpyxl` >=? (already present) for XLSX; add `odfpy` for ODS; verify/add `xlrd` for legacy XLS since pandas dropped built-in xlsx support from xlrd 2.x but xlrd still handles `.xls`.
- **Object Storage**: MinIO client >=7.2.5 via `minio_service`, unchanged.
- **Testing**: pytest / pytest-mock >=8.1.1, httpx >=0.27.0 test client — add fixture binary files under `{backend}/tests/fixtures/upload_formats/`.
- Per `tech-stack.md`: no CI/CD detected in this project — these tests only protect against regressions when run locally/manually until CI exists.

### Testing

- Test file location: extend `{backend}/tests/test_upload.py` (existing file) with per-format cases, or add a new `{backend}/tests/test_upload_formats.py` if the existing file would grow unwieldy — either is consistent with the existing flat `tests/` layout.
- Framework: pytest + `pytest-asyncio` (`@pytest.mark.asyncio`) + `httpx.AsyncClient(transport=ASGITransport(app=app))`, exactly as in the existing `test_upload_csv`/`test_preview_data_success` tests. DB is mocked via `app.dependency_overrides[get_db] = lambda: mock_db` with `AsyncMock(spec=AsyncSession)`; MinIO is mocked via `mocker.patch("app.api.endpoints.upload.minio_service.upload_file", ...)` / `get_file_stream`. `{backend}/tests/conftest.py` stubs `minio`, `sqlalchemy`, `alembic`, `aiomysql`, `pydantic_settings` as `MagicMock` modules so the suite runs without Docker services — follow this existing mocking approach exactly, do not spin up real MinIO/MySQL in tests.
- Test types required: a hard regression test for the existing CSV path (byte-identical response contract — the existing `test_upload_csv` test already covers this and should keep passing unmodified), per-format happy-path tests (all 6 formats), and per-failure-mode tests (corrupt, empty, password-protected) each asserting a `400` with the specific actionable message text — never asserting a `500`. Update `test_upload_invalid_type` per Subtask 4.4 since its current assertion text (`"Only CSV files"`) no longer matches the new content-sniffing rejection path.
- `import_status`/`data_type` assertions: `process_detected_type` runs via FastAPI's `BackgroundTasks`, which execute within the same ASGI request lifecycle that `AsyncClient` awaits — so by the time `ac.post(...)` returns, the background task has already run against the mocked DB/MinIO. Assert `dataset_record.import_status` was set at creation time (before the background task even runs, per Subtask 5.2) directly via the `mock_db.add.call_args` object added to the session, following the existing `assert mock_db.add.called` pattern in `test_upload_csv`.
